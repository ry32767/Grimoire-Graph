# 実装の委任

**委任するもの**：やることが file/line レベルまで特定できた実装・テスト作成・機械的な追随変更。
**委任しないもの**：設計判断・仕様解釈・バランス調整の方針（本体が決めてから渡す）。

## 委任プロンプトの定型（この規約を必ず同梱する）

```
Grimoire-Graph の実装作業。以下を実装し、指定の検証まで通してから要約を返す。

作業内容: <file:line まで特定した具体的な変更内容と理由>

このリポジトリの規約（違反しない）:
- コメントは日本語で簡潔。any 禁止（unknown で絞り込む）
- ゲームロジックは src/game/ の純粋関数（React/Canvas に依存させない）
- マジックナンバーは src/data/constants.ts に集約
- テストは既存の describe/ヘルパの命名・スタイル（日本語テスト名）に合わせる
- 挙動を変えたら「この入力でこの出力」を assert する回帰テストを同時に書く

検証: npm run typecheck && npx vitest run <関係する test ファイル> 2>&1 | tail -20
（フルテスト npm test は本体が最後に1回流すので不要）

返すもの（それ以外返さない）:
- 変更ファイルと要点（diff 全文は不要・数行で）
- 追加/変更したテスト名と、その検証コマンドの末尾出力
- 判断に迷って仮置きした点（あれば）
```

## 並列化の目安

- 変更が**互いに別ファイル**（例：ロジック修正／テスト追加／docs 同期）→ Workflow の
  `parallel` で同時に。docs は /docs-sync の雛形をそのまま使う。
- **同じファイルを触る**チャンクは並列にしない（1体に順番でやらせるか、
  どうしても並列なら `isolation: 'worktree'` で分けて本体がマージする）。
- 委任後、本体は必ず：変更点の要約を読んで意図どおりか確認 → /verify-loop で
  フル検証 → コミット（サブエージェントの報告を鵜呑みにしない・AGENT_PLAYBOOK §3）。

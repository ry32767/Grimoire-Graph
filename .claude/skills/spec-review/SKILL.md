# 仕様照合レビュー（Spec Compliance Review）

過去のセッションで繰り返し行われてきた総点検作業（PR #41〜#43 ほか）。仕様書は**実装の契約書**であり、乖離は「仕様が正」を原則として実装側を直す。

## 手順

### 1. 対象範囲を決める

- ユーザーが機能・セクション（例：§3.5 暴発、敵AI）を指定していればそこに絞る。
- 指定がなければ `graph_mage-spec.md` の「2. 機能一覧」の受け入れ条件を上から順に照合する。範囲が広い場合は Explore サブエージェントで分担してよい。

### 2. 突き合わせ

各受け入れ条件・仕様記述ごとに：

1. 仕様の記述（挙動・数値・式）を正確に読む。
2. 対応する実装を `src/game/`（ロジック）、`src/data/constants.ts`（定数）、`src/`（UI・描画）から探す。
3. 次の3分類で判定する：
   - **○ 一致** — 仕様どおり
   - **× 乖離** — 未実装／挙動が違う／定数・式の値がズレている（`file:line` と仕様の該当箇所を必ず記録）
   - **？ 仕様不備** — 仕様が曖昧・矛盾していて判定できない

### 3. 対処

- **×（乖離）**：仕様に合わせて実装を修正する。仕様側が古い（実装の方が意図的に進んでいる）と判断できる根拠がある場合のみ、spec/docs 側を実装に同期する（`docs-sync` スキル参照）。どちらが正か判断できなければユーザーに確認する。
- **？（仕様不備）**：勝手に決めず、`graph_mage-spec.md` の「9. 未決定事項 / 要確認」にチェックボックス形式で追記して報告する。

### 4. 検証と報告

- 修正したら `verify-loop` スキルの手順で全 green を確認する。
- 報告は「○×？の一覧（仕様の該当箇所 → 実装の該当箇所）」＋「修正内容の要約」の形式にする。

## 注意

- 数値の照合は目視でなく、`src/data/constants.ts` 等の実値を読んで spec/docs の数値と**一字ずつ**比較する。過去にも定数ズレが頻出している。
- 描画・演出系の仕様（07-animation.md 相当）はコードリーディング＋可能なら手動確認とし、確認方法を報告に添える。

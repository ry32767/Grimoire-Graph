# 検証ループ（Verification Loop）

このプロジェクトで**最も重要な規約**。機能を「完了」と宣言する前に必ずこのループを回す。

## 手順

1. 4つの検証コマンドを順に実行する：

   ```bash
   npm test          # Vitest（受け入れ条件に対応するテスト）
   npm run lint      # ESLint
   npm run typecheck # tsc --noEmit
   npm run build     # tsc --noEmit && vite build
   ```

   ※ 失敗の切り分けを速くするため、並列でなく**この順で1つずつ**実行し、失敗したら即座に出力を読む。

2. 今回の作業に対応する `graph_mage-spec.md` の**受け入れ条件**を1つずつ ○× で照合する。
   - 対象機能のセクションは `grep -n "受け入れ条件" graph_mage-spec.md` とその周辺で特定する。
3. 1つでも失敗・未達があれば、**原因を直して手順1に戻る**。
4. 仕様（挙動・数値・受け入れ条件）を変えた場合は、`docs-sync` スキルの対応表に従い `graph_mage-spec.md` と `docs/` を同じコミットで更新する。

## 完了報告のルール

- テスト・Lint・型・ビルドのいずれかが赤いまま「完了しました」と言わない。
- 受け入れ条件の照合結果を ○×リストで簡潔に報告する。
- 描画・アニメーション・体感系の条件は自動テスト不可 → 手動確認扱いとし、**何をどう確認したか（または確認できなかったか）を一言添える**。
- 受け入れ条件を満たせない原因が仕様の不備にあるときは、勝手に進めず `graph_mage-spec.md` の「9. 未決定事項 / 要確認」に追記して相談する。

## よくある落とし穴

- `npm run build` は `tsc --noEmit` を含むため、typecheck が通っても build 固有の Vite エラー（アセット・環境変数）が出ることがある。両方回すこと。
- ゲームロジックのテストは `src/game/` の純粋関数を対象にする。React state / Canvas に依存するテストは書かない。

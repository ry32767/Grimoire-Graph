# ドキュメント同期（Docs Sync）

**ドキュメントが実装とズレた状態を「完了」と呼ばない**のがこのプロジェクトの規約。仕様を変えたら、コードと同じ作業（できれば同じコミット）で spec と docs を更新する。

## 対応表：何を変えたら、どこを直すか

| 変更したもの | 更新するドキュメント |
|---|---|
| 受け入れ条件・機能仕様・未決定事項 | `graph_mage-spec.md` |
| バランス定数（`src/data/constants.ts` の数値） | `docs/08-constants.md`（＋影響する計算の説明） |
| 計算式（物理・属性・強度・相性・ダメージ・状態異常） | `docs/02-calculations.md` |
| 関数カタログ・z場・自由入力 | `docs/03-functions.md` |
| 魔法の挙動（発射型/軌道型/結界/暴発/パリィ/障害物） | `docs/04-magic.md`（暴発・不安定化は `docs/04b-misfire-instability.md`） |
| 敵・敵AI・系統・ロール | `docs/05-enemies.md`（系統は `05b-enemy-archetypes.md`、図鑑は `05c-bestiary.md`） |
| ステージ・敵配置・障害物 | `docs/06-stages.md`（難易度設計は `06b-difficulty-framework.md`） |
| 描画・演出・音・配色 | `docs/07-animation.md` |
| 型・ターン進行・解決順序・モジュール構成 | `docs/09-data-model.md` |
| 概要・世界観・画面フロー・パーティ | `docs/01-overview.md` |

## 手順

1. `git diff`（または今回の作業内容）から、変更が上の表のどの行に当たるかを列挙する。1つの変更が複数行に当たることが多い（例：定数変更 → 08-constants.md ＋ 02-calculations.md の計算例）。
2. 各ドキュメントの該当箇所を開き、**`src/` の実値を読んで転記する**。推測・記憶で数値や式を書かない。
3. 章をまたぐ影響（定数変更で計算結果が変わる等）は関連ページを全て直す。
4. 新しいトピックが必要なときは、先に `docs/README.md` の目次に追記してから本文ページを書く。
5. 更新後、数値・式・テーブルが実装と一致しているか再度 `src/` と突き合わせて確認する。

## 更新不要なケース

- 挙動・数値・式が一切変わらない純粋なリファクタ。
- ただしモジュール構成（ファイル分割・関数の移動）を変えた場合は `docs/09-data-model.md` の構成説明が対象になるので注意。

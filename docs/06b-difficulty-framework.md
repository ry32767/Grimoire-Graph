# 06b. 難易度フレームワーク（LVL）とステージ仕様（全5面・#69）

> 05-enemies / 05b-enemy-archetypes / 04-magic / 04b-misfire-instability を踏まえ、**LVL という単一パラメータ**で「数値・使える関数・登場パターン」を連動して解放する。06-stages.md の内容をこのフレームワークで置き換える。
> 敵は面ごとの新顔ではなく、**4系統（攻撃パターン）がティアで強化再登場**する構成。系統ごとの命名・モチーフ・強化点の整理は [05c-bestiary.md](05c-bestiary.md) を参照（本ファイルとは同一の数値を指す）。

## 1. LVL とは何か

`LVL`（1〜7、原則ステージ番号と一致）は、そのステージで**敵がどこまで強く・賢く・多彩になれるか**の上限を表す整数パラメータ。1つのステージ内でも、雑魚は低め・精鋭やボスは高め、のように**敵ごとに `LVL` を個別に持たせてよい**（`enemyLevel ≤ stageLevel` が基本）。

LVL は3つの軸を同時に解放する：

```
LVL が上がる ⇒ ① 数値（HP・威力・castMag・発射頻度）が上がる
             ⇒ ② 使える軌道 family／z場が増える（単純→複雑）
             ⇒ ③ 使える攻撃パターン（火力型/迂回型/暴発型/守護型）が増える
```

これにより「LVLさえ言えば、その敵がどのくらい強く・何ができるか」が一意に決まる。ステージ定義者は各敵に `level` を振るだけでよい。

## 2. ① 数値のスケール表

`castInitialSpeed` は**全敵・全LVLで固定**（`castInitialSpeed = 8`。既存06-stagesの基準値をそのまま採用し、LVLでは変化させない）。速度差による有利不利を無くし、**関数の選び方・z場・タイミング**だけで難度が上がるようにする。

> **例外（#63）**：第4面（封印帯）の崩し手3体だけ `castInitialSpeed=6.5` に落とす。封印帯の「前」（部分カバーの硬い岩塊の陰・半身）に配置され直し、曲射の暴発弾が岩塊を回り込んで初手から味方の目前に届くため、反対極の結界1枚（迎撃減速＋極手前の自然減速）で1本ずつ確実に受け切れる速度に調整した個体固有の例外（`enemy()` ファクトリの `opts.castInitialSpeed` で明示上書き）。他の全敵・全LVLでは引き続き `8` 固定。

| LVL | HP倍率目安 | castMag（z強度） |
|---|---|---|
| 1 | ×1.0（基準90〜130） | 3 |
| 2 | ×1.15 | 3 |
| 3 | ×1.3 | 3.5 |
| 4 | ×1.5 | 3.5 |
| 5 | ×1.65 | 4 |
| 6 | ×1.85 | 4〜5 |
| 7（ボス/精鋭） | ×2.0〜3.0（ボスは単体で大きく超過） | 5 |

> 実数は06-stages.mdの既存値（第1〜7面）とおおむね整合するよう基準化した。HP倍率は「敵の基礎HP100」を1.0とした目安。

### 発射頻度（パターン別ルール・LVLでは変化させない）

発射頻度は LVL でスケールせず、**パターンごとに固定**する：

| パターン | 発射頻度 |
|---|---|
| 火力型 | 毎ターン |
| 迂回型 | 毎ターン |
| 暴発型 | **低め**：`fireEvery=2`（2ターンに1回）。複数体は `fireOffset` でずらす |
| 守護型 | 攻撃はしない（結界は毎ターン張り直す。張れなかったターンも持続結界＝`owner='enemy'` の周回が破壊されるまで残り、迎撃・回復を続ける・#61） |

- 暴発型・守護型を低頻度にするのは、**プレイヤー側の対応（結界の張り替え・迎撃）に猶予を持たせるため**。特に第4面（封印帯）の崩し手3体が同時に毎ターン撃つと理不尽になりやすいので、ここで頻度を絞る。
- 火力型・迂回型は毎ターン攻撃してよい（既存 attacker/breaker の想定どおり）。

## 3. ② 関数解放表（軌道 family／z場）

05b-enemy-archetypes.md §2・§3 の一覧を、LVLで段階解放する。

### 軌道 family

| LVL | 解禁される family |
|---|---|
| 1 | `line` のみ |
| 2 | `arc`（2次）、`abs`（絶対値・V字）追加（#47） |
| 3 | `wave` 追加（**迂回型・暴発型は使用しない**。現行図鑑では他パターンでも未使用、将来の追加個体向けに予約） |
| 4 | `spiral` 追加（主に守護型の結界形状）、`exp`（指数）追加（#47でLVL5→LVL4に前倒し） |
| 5 | `poly34`（3〜5次）追加（#47でLVL6→LVL5に前倒し） |
| 6 | 新規 family なし。既存 family の組み合わせを高度に使う段階 |
| 7 | 全 family を状況に応じ自由に選択（複数 `families` 併用が標準） |

> **迂回型が使えるのは `abs`／`arc`／`poly34` のみ**（`line`/`wave`/`exp`/`spiral`不可・05b §2）。**暴発型も同じ制約を継承**する。この制約はLVLに関わらず常に有効（LVLで解除されない）。

### z場

| LVL | 解禁される z場 |
|---|---|
| 1〜2 | 一定のみ |
| 3〜4 | sin/cos 追加 |
| 4〜5 | **守護型の方向づけられた場**（脅威方向に偏った非一様z場）が使用可能に（#47でLVL7→LVL4〜5に前倒し。中難度個体の強化点として導入） |
| 5 | 指数関数 追加 |
| 6 | 「その他」（ステージ固有式）＋**極（1/x型・暴発型専用）**が使用可能に |
| 7 | 守護型の**交互張り＋方向づけの併用**（両方を同時に使う最上位個体）＋**過励起**（非一様場に限り `|z|>zRef` を許し、本番物理で自壊しない配分だけ採用・#71） |

> 05b §2 の「迂回型・暴発型は `abs`/`arc`/`poly34` のみ」は全 LVL で常に有効な制約（LVLで解除されない）。

## 5. 障害物（壁）の仕様指針

04-magic §4.4 の壁種別（`normal`/`fragile`/`tough`/`unbreakable`）を、LVLとステージのテーマに応じて配置する指針。

| 壁種別 | 使う場面 | LVL目安 |
|---|---|---|
| `fragile`（もろい） | 「壊せる」を教える壁。一撃で大きく崩れる（`carveScale=1.7`）。現行配置では第2面の瓦礫リング `ring(0,2,4,'neutral','fragile')` と第3面のもろい祭具の囲い `wall(-15,-9,-18,1,'neutral','fragile')` のみ | 1〜3 |
| `normal`（属性付き） | 相性（反対極で安く削れる）を学ばせる基準種別。現行配置では**第3面の教材壁**（横仕切り `wall(-20,-1,5,2,'light')`・祭壇の影のカバー `wall(-2,2,16,1,'dark')`）のみ。他の面の内部戦術壁は `tough` に統一（`tough` でも相性は掛かる） | 3 |
| `tough`（頑丈） | **内部の戦術壁の基本種別（第2〜7面）**。術の削りがほとんど通らず（`carveScale=0.32`・`lossScale=1.7`）、迂回か多ターンの掘削を要求する | 2〜7 |
| `unbreakable`（壊れない） | 部屋の囲い（`chamber`/`roomWalls`）・第4面の封印核。迂回・回廊通しを**強制**する | 全面（囲い）／テーマ的な「核」 |

### 配置の型（`pillar`/`block`/`disc`/`wall`/`colonnade`/`spiralArm` を使用）

- **序盤**：単発の壁（`pillar`や`wall`1枚）で「削れる／越えられる」を学ばせる。
- **中盤**：`colonnade`（列柱）で複数属性を混在させ、相性の使い分けを要求。
- **終盤**：`wall`の多段重ね＋`block`の`unbreakable`核を組み合わせ、迂回と削りの両方を要求。
- `spiralArm`・`colonnade` は省略可能な `kind` 引数を持ち、面ごとに `tough` 等を指定できる（`stageBuilders.ts`。第4面の渦・第5面の列柱で使用）。

### 5.4 レイアウト設計の一般則（#69：面ごとの決め打ちをやめ、全面へ機械的に課す）

`src/data/stages.test.ts` の describe「レイアウトの一般則（#69）」が、面ごとの座標ではなく**条件そのもの**を検査する。新しい面を足しても同じ規律が自動で効く。

| 原則 | 内容 |
|---|---|
| **直線を通さない** | 第1面以外は、どの味方からどの敵へも直線が通らない（必ず遮蔽が挟まる） |
| **味方は散開** | 相互距離 ≥10・横幅 ≥18・前後差 >2（横一列に並べない）。3人が別々の射線と遮蔽を持つ |
| **結界の余地** | 各味方の周囲**半径 7.5 に素材が無い**（結界は壁に触れると霧散する・#34） |
| **迂回型は陰に** | attacker は最寄り味方への直射線が遮蔽で塞がれる＝曲射だけが届く |
| **火力型は守護の内側** | breaker は守護型／ボスから **≤6**（`enemyGuardRadius−1`）＝結界に覆われる位置 |
| **暴発型は半身を隠す** | ruptor は至近 8 以内に遮蔽を持つ |
| **攻め手は必ず残す** | 敵 → 各味方に素材に触れない経路が存在する（＝敵AIが曲げて攻撃できる） |
| **内部の壁は硬い** | 戦術壁・柱は `tough`。例外は教材用の `normal` 壁・`fragile` 瓦礫・部屋の囲い/封印核の `unbreakable` |

**直線を断つ「三列の千鳥列柱」の幾何（#69）**：等間隔の柱をピッチ **12** で並べ、列ごとに **1/3 ピッチ（=4）** ずつ横へずらして三列置く。柱の直径 `2R=4.8` は `12/3=4` より大きいので三列の影が横方向で必ず重なり、**どの縦線も必ずどれか1本に当たる**。一方で同じ列の柱どうしは `7.2` 空いており、曲げれば素材に触れずに抜けられる車線が残る（`wideClearance=1.5` の広い車線が取れる幅）。斜めの射線は柱だけでは塞ぎ切れないので、崩落壁・壊れた塔・ボスの盾を足して塞ぐ。

**なぜ「広い車線」が要るか**：敵弾は初速 8、`tough` 壁の削りコストは中立で `7×1×1.7=11.9` ＝**一度触れただけで失速して消える**。したがって隙間のギリギリを縫う経路は family フィットの誤差でほぼ確実に潰れる。経路探索は素材から `wideClearance` 離れた経路を優先して探し、隙間の**中心**を通す（[05-enemies.md](05-enemies.md) §5.4）。


### 5.5 ステージスケール（面ごとに可変・#49）

面ごとに「サイズ」を持たせ、場の半径 `rField` をスケールで決める（手描き仕様のスケッチに対応）。
`rFieldForSize(size)=round(25+(size-1)·35/3)`（size1→25, 1.5→31, 2→37, 2.5→43, 3→48, 3.5→54, 4→60）。
**第1面=最小25**、**最大＝第5面②=60**（約2.4倍）。面が進むほど場が広がるが、戦闘は中央付近で成立させ、広がりは余白・迂回の余地として使う。

| 面 | サイズ | 実装スケール（`rField`） | 理由 |
|---|---|---|---|
| 1 | 1 | `25` | 最小の門の間。狭さがかえって見通しやすい |
| 2 | 2 | `37` | 崩れた回廊（柱列＋崩落した大壁） |
| 3 | 3 | `48` | 列柱の広間。三列の千鳥列柱と塔を置く余地 |
| 4 | 3 | `48` | 封印帯（封印核＋崩し手3体が主役） |
| 5 | 2.5→4 | ①上層 `43` → ②中層 `60` → ③下層 `60`（`bossPhases[].rField` で拡大） | ①列柱の間から床崩落で②崩れた大広間へ**拡大**。②③は同じ大円 60 |

> 大アリーナでも弾が対岸へ届くよう、回転方式のサンプリング上限 `rotateXMax` は `max(48, 1.6·fieldR)` と `fieldR` に追従する（`coords.ts`。既定 fieldR=30 では 48 のまま）。盤面は**ズーム/パン**で拡大縮小して見やすくできる（`BattleCanvas`：＋/−ボタン・ホイール・ピンチ／2本指パン。面/フェーズ遷移でリセット）。
> 実装値は `src/data/stages.ts` の `Stage.rField` / `BossPhase.rField`（`rFieldForSize`）。座標は「壁・敵が場内（`dist < rField`）に収まる」よう調整済み。`rField` は `BattleState.rField`（`createBattleState` が取得・`applyBossPhases` が反映）を通じて `Trajectory.fieldR` に伝わり、`coords.sampleTrajectory` の `inField` 判定・描画ビューポート（`unitsRadius`）・敵AI計画・味方プレビューが同じ半径を参照する。

**高難度面ほどスケールを広げる理由（#49）**：フィールドが広いほど、壁を複雑に・強度の高い種別（`tough`/`unbreakable`）を多めに配置できる。特に**迂回型の高次関数（`poly34`＝3〜5次）は、広い空間でこそ大きくうねる軌道を描く余地が生まれ、真価を発揮する**（狭い場では S字を描く前に壁や場外に達してしまう）。第3〜5面はこの余地を優先してスケールを大きめに取る。

### 5.6 回り込み対策（翼壁・wing wall・#50）

> **更新（手描き仕様・部屋モデル）**：現行の壁配置は「**円の中に壁で囲った部屋**」（`roomWalls`）に変更した。四方を壁で囲うため側面の回り込みは構造的に起きず、**翼壁（`wingWall`）は廃止**した（部屋の囲いがその役割を内包する）。以下は経緯の記録。実装は第1面が `roomWalls(...)`、第2〜5面が `chamber(...)`（#69：各辺にドア＝開口を空けられる部屋。現状はいずれも開口なし）。開けた円で戦う第5面②③のボスフェーズは囲わない。



**問題（実プレイで確認・スクリーンショット参照）**：`colonnade`や`wall`は `x∈[-18,18]` 程度の帯にしか壁を置かないため、場の境界（円形フィールド、半径`rField`）はそれより外側まで広がっている。結果、**迂回型AIが壁の帯の外側（境界ぎりぎり）を大きく迂回するだけで、壁の存在ごと無視して直撃できてしまう**。壁の相性・脆さ・迂回のかけひきが、一切機能しなくなる。

**原因**：壁の帯の幅（例：`x∈[-18,18]`）が、場の境界（例：`rField=30`）より内側で止まっており、帯の両端から境界までの三日月状の空間が素通りできる迂回路になっている。

**対策：翼壁（wing wall）**：壁の帯の**両端から場の境界近くまで**、追加の壁を伸ばして側面を塞ぐ。

```
wingWall(帯の端のx, 境界近くのx, y0, rows, kind="unbreakable")
```

- 既存の`wall(x0,x1,y0,rows,element,kind)`ヘルパーをそのまま使い、`x0`を帯の端（例：`18`）、`x1`を境界近く（例：`27`〜`28`、`rField`より少し内側）に設定するだけでよい。左右対称に配置する（`x0=-27〜-28, x1=-18`も追加）。
- **種別は`unbreakable`を推奨**：翼壁は「意図した通り道を通らせるための境界」であって、削って崩す対象ではない。`tough`にすると「迂回する代わりに翼壁を地道に削る」という新しい抜け道が生まれ、根本解決にならない。
- 中央の帯（`colonnade`や`fragile`壁など、元から意図されていた通り道）はそのまま残す。**迂回型・プレイヤーの双方が、翼壁の内側にある“意図した通り道”を通らざるを得なくなる**――迂回するなら壁の隙間（個々の柱の間）を縫うか、脆い部分を破壊するかの二択になる。
- 味方側にも同じ制約がかかる（翼壁は敵味方どちらの弾も塞ぐ）。これは公平で、むしろ「壁を使ったかけひき」が両者にとって初めて意味を持つようになる。

**適用対象の洗い出し**：既存6面（第2〜7面）はいずれも壁の帯が境界より狭く、同じ迂回み抜けが起こりうる。優先度つきで対応する。

| 面 | 現状の壁の帯 | 対応状況 |
|---|---|---|
| 2 | `colonnade(-18,18,...)` | **対応済み**（スクリーンショットで実際に確認された箇所。§6 第2面に翼壁を追加） |
| 3 | `wall(-18,18,...)`＋塔・芯柱 | **対応済み**（全幅壁を2段に厚み増＋障害物全体のy範囲を覆う翼壁を追加。§6 第3面） |
| 5 | `colonnade`左右＋鏡枠`pillar(±18,...)` | **対応済み**（鏡枠のさらに外側に翼壁を追加。§6 第5面） |
| 6（旧番号） | 左右 `tough` 封印壁（中央回廊）＋光柱 | **対応済み**（#63で封止。#69 で新・第4面へ再編・§6 第4面） |
| 7 | 各層の`colonnade`/`wall` | **対応済み（①上層のみ）**：①矩形の間に翼壁を追加。②③は開けた大円（サイズ4・拡大）で、隠れ場所の少ない開けた設計が意図（翼壁なしで許容） |
| 4 | 敵が包囲配置（§6 第4面） | **不要**（そもそも正面の帯という概念がなく、全方位から来るため回り込みが成立しない） |

> ⚠️ ここでの「対応済み」は**設計レベルの修正**。実装後、実際のAI軌道（`enemyPlanning/` の経路探索・05-enemies §5.4）で本当に迂回み抜けが起きないかを、各面ごとにプレイテストで確認する必要がある（座標の計算は手作業のため、誤差や見落としがありうる）。

## 6. ステージ別仕様（全5面・#69）

各面：`LVL`（面の上限）／テーマ／壁配置／敵構成／`mechanics`／暴発・instability 関連イベント。
**座標・HP などの実装値は [06-stages.md](06-stages.md) が正典**（ここは設計意図を書く）。

> **#69 の再編**：想定プレイ時間 15〜30 分に合わせて 7 面 → **5 面**へ集約した。
> 旧・第2面（通路）＋第3面（踊り場）→ 新・第2面（崩れた回廊）、
> 旧・第4面（螺旋）＋第5面（深層の広間）→ 新・第3面（列柱の広間）、
> 旧・第6面（封印帯）→ 新・第4面、旧・第7面（大広間）→ 新・第5面。
> 暴発デモ（RUPTOR_DEMO）は新・第3面へ、初回崩壊の保証面は新・第4面（`firstCollapseStage=4`）へ移した。

### 第1面 ― 門（LVL 1）

- **テーマ**：命中だけを学ぶ。`mechanics: {obstacles:false, enemyFire:false}`。
- **スケール**：`rField=25`（サイズ1）。装飾の部屋枠のみ。
- **敵**：石像の番人（attacker・`line`・HP90）1体。

### 第2面 ― 崩れた回廊（LVL 2〜3）

- **テーマ**：遮蔽・相性・迂回をまとめて学ぶ。`mechanics: {obstacles:true, enemyFire:true}`。
- **スケール**：`rField=37`（サイズ2）。
- **地形**：崩落した大壁（`normal`＝反対の理で速く削れる教材壁・開口2か所）＋等間隔の柱4本（`tough`）＋崩れた塔2基＋瓦礫。**崩落口の真下に柱**が来るので、開口を狙った直線も通らない。
- **敵**：迂回型2体（塔の陰）＋火力型1体。守護型はまだ出さない。
- **学習**：「まっすぐは通らない → 山なりに越えるか、反対の理で削る」。

### 第3面 ― 列柱の広間（LVL 4〜5）

- **テーマ**：守護型＋火力型の連携／結界で守る／**暴発の顔見せ**（RUPTOR_DEMO）。
- **スケール**：`rField=48`（サイズ3）。
- **地形**：**三列の千鳥列柱**（ピッチ12・1/3ずらし・`tough`）＋折れた列柱＋壊れた塔（射手のカバー）＋崩落壁＋瓦礫。
- **敵**：守護型（`directedAura`）＋その結界の内側の火力型2体＋塔の陰の迂回型（`slipThrough`）＋壁狙いの崩し手1体（低頻度・暴発デモ）。
- **学習**：「守護の結界ごと崩すか、内側の火力型を先に落とすか」「暴発とは何か」を見せる。

### 第4面 ― 封印帯（LVL 6・初回崩壊）

- **テーマ**：暴発の**誘発**と防御。崩し手3体＋守護型（最上位：交互張り＋方向づけ併用）。ここで初回崩壊（グリモワール救済）。
- **スケール**：`rField=48`（サイズ3）。
- **地形**：部屋の囲い＋砕けぬ封印核（`unbreakable`・番人の盾＝正面突破不可）＋二列の千鳥柱＋崩し手の部分カバー `disc`×3（`tough`・半身を隠す）＋崩れた封印壁＋瓦礫。
- **#63 の調整方針（#69 でも維持）**：
  1. **番人を前衛化**。単純な最寄り狙いの連打はまず番人へ吸われ、その間に崩し手の暴発が積み上がる＝「結界で防いでから番人を崩す」の手順を要求する。
  2. **崩し手3体は封印帯の「前」**に置き、それぞれ部分カバーの `tough` 岩塊の陰に半身を隠す（§5.4 の迂回型カバー原則を暴発型へ適用）。曲射の暴発弾は岩塊を回り込んで初手から味方の目前へ届く一方、カバーは半身に留め、対処プレイの担当射線は塞がない。岩塊は**味方の半径7.5の結界に触れない距離**を厳守する（結界は壁に触れると霧散する・#34。`stages.test.ts` で固定）。
  3. 崩し手の弾速を `castInitialSpeed=6.5`（既定8からの例外・§2）に落とし、HP を175へ、属性を光2・闇1に振る（反対極弾がひるみでなく DoT になり、ひるみロックだけで詠唱を止め続ける対処を封じる）。
- **暴発/instability**：初回崩壊トリガー面（04b §4b.2・`firstCollapseStage=4`）。
- **バランス回帰テスト（`src/game/balance.test.ts`）**：この面は「両極の持続結界（闇r6・光r7）→ 光弾のひるみロック → 曲射で番人」の対処プレイで**無被弾・膜の消費≤2**でクリアできること（原則B＝勝ち筋の存在証明）を固定する。

> ⚠ **#69 時点のバランス状況（要再調整）**：原則A「防御しない連打では勝てない」は**最終面（第5面）でのみ**成立している。第2〜4面は連打ボットでもクリアできてしまう。原因は #69 でおまかせ照準に経路探索フィットを入れ、味方の命中力が大きく上がったこと（柱の隙間を縫う曲線を自動で見つける）。難易度そのものの再調整は別タスクとして残している（`balance.test.ts` の冒頭コメントにも明記）。


### 第5面 ― 大広間（LVL 7・ボス戦・HPフェーズ制／#45）

- **テーマ**：総力戦。ボスは**多重詠唱**（05b §5.5）で「火力型」「迂回型」の弾を独立に複数本、同時に放つ。HPが1/3減るたびに床が崩れ、下の階層へ落下する――**3層構成**で最後は断末魔の暴発3連。
- **mechanics**：`obstacles: true`／`enemyFire: true`。

#### HPフェーズと同時発射数

| フェーズ | HP範囲 | 同時発射数 `castCount` | 使うパターン | 床（アリーナ） | `rField` |
|---|---|---|---|---|---|
| ① | 100%〜66%超 | **2** | 火力型・迂回型から2つ選ぶ（重複可） | 矩形の間（上層） | `43` |
| ② | 66%〜33%超 | **2**（変わらず） | 同上 | 崩落後の開けた大円 | `60` |
| ③ | 33%〜0%超 | **3** | 同上（3つとも火力/迂回のプールから選ぶ） | 大円のまま・眷属間引き | `60` |
| ④断末魔 | HP ≤ 0（撃破確定後の最後の一手） | **暴発 3連**（固定・パターン選択なし） | 暴発型（z場の極 ×3、同時） | 大円のまま・ボス単独 | `60` |

> `rField` は床崩落で段階的に**拡大**する（#49・§5.5・手描き仕様のスケッチ ①→②）。②③④は同じ大円 60（ボス y=26 を場内に残す）。

- **床崩落の演出**：フェーズ①→②、②→③の境界（HPが66%・33%を下回った瞬間）で、床にひびが走り、ボスと三人ごと**下の（より広い）階層へ落下する**。落下中は1ターン分の暗転演出を挟んでよい（味方の行動はスキップ、被弾もなし。※現状は未実装・テンポ優先）。
- **アリーナの違い**：
  - **①上層**（`rField=43`）：部屋の囲い`roomWalls(-20,20,-30,30)`（`unbreakable`）＋`block(-5,-4,4,3,light,tough)`（守護者の盾・硬い）＋迂回眷属のカバー`wall(-12,-5,9.4,1,light,tough)`（至近の光壁。おすすめの直射は掘削で数ターン〔実測4〕後に開通＝連打の進行〔眷属撃破→ボス削り→フェーズ移行→開けた大円で敗北〕を止めない・§5.4）。矩形の間。
  - **②中層**（`rField=60`）：開けた大円。柱は崩れて短い壁 `wall(-16,-4,-3,1,dark,tough)`／`wall(4,16,-3,1,light,tough)` のみ（`openArena`・硬い）。隠れ場所が少なく被弾しやすい代わりに軌道の自由度が高い。
  - **③下層**：障害物なし・眷属間引き（`cullMinions`）でボス単独へ。逃げ場が少なく、3同時発射をまともに受ける緊張感を出す。④断末魔（HP0）へ繋ぐ。
- **随伴**：眷属（迂回型1体・火力型1体、既存どおり）は上層・中層に配置し、下層（フェーズ3）ではボス単独に絞る（3同時発射との合わせ技で過負荷にならないよう間引く）。
  - **バースト即死時も最終フェーズを先に適用する（バグ修正）**：ボスの HP がフェーズ閾値（33%）を跨がずに、1ターンのバースト（強命中や暴発 AoE の巻き込み）で一気に0へ落ちても、**最終フェーズの `cullMinions`／アリーナ差し替えを先に一括適用してから**断末魔を晒す。以前は `applyBossPhases` が `boss.hp<=0` で早期 return し、フェーズ未到達だと眷属を間引かず、上層/中層アリーナで**眷属を従えたまま断末魔が発生**していた。現在は `applyBossPhases` がボス撃破（hp≤0）を「最下層まで一気に落ちた」とみなして最終フェーズを適用する（`markFinaleIfBossDown` は予約のみで、間引きは `applyBossPhases` が担う）。これで断末魔は常に**ボス単独の最後の一手**になる。

#### 断末魔（暴発3連・撃破の最終演出）

- ボスの HP が 0 以下になった瞬間、通常の勝敗判定より先に**最後の一手**として、暴発型パターンの弾を3本、独立に計画して同時発射する（05b §5.5「多重詠唱」の`castCount=3`・`patternsThisTurn=[暴発型,暴発型,暴発型]`固定。各弾の狙いは`planRuptorShot`と同じロジックで個別に決まる――基本は3人へ1発ずつ、揃わなければ低HP者へ集中）。
- **暴発型の原則どおり、この3本も味方の弾と全く同じ物理法則・干渉ルールに従う特例なしの弾**（05-enemies §5.4b・05b §4）。極（z場の1/x型）に到達する前に、その弾と**反対極**の結界またはパリィで速度を0にすれば、暴発は起きない。同極では素通りする。**移動・接近は暴発型の原則どおり迂回型と同じ**（`line`不可・障害物は避ける）。
- **`instability` は通常どおり計上する**：迎撃されず解決した暴発1本につき `instability +1`（最大+3）。**3本すべてを結界かパリィで防ぎ切れば、`instability` は1つも増えない**――つまり道中で膜を摩耗させすぎていなければ、ここは安全に乗り切れる。
- 逆に、このタイミングで `instability` が `MISFIRE_LIMIT`（04b §4b.2）に達してしまえば、**ボスの HP が 0 であっても通常どおりステージ全体暴発＝ゲームオーバーになる**（特別な免除はしない）。膜メーターは初回崩壊（第六層）以降ずっと可視化されているため、プレイヤーは道中の使用と、この最終防御に必要な余力を、常に自分で管理できる。
- ダメージ自体（防げなかった分）は通常の暴発仕様どおり有効（常に最大威力・両極性・両状態異常）。
- 3本の結果（防げた/防げなかった）に関わらず、この一手を解決したのちに勝敗判定に進む（instability が上限に達していなければステージクリア）。

#### ボスの見た目（フェーズごとの外見変化・#51）

> 種族共通の撃破演出（05c §6.5）は使わず、ボス専用の多段演出とする。05c §6.5「魔導書の守護者」の行はこの節を正典として参照する。

**基本デザイン**：《古代式の魔導書》と《天秤》を象った巨大な構成体。体は書物のページを模した板状の装甲で構成され、**左半身は光（金）、右半身は闇（紫）**で左右対称に色分けされる（どちらが光/闇かは実装時に固定）。全身に古代式の刻印（文字状の紋様）が浮かび、胸の位置に小さな天秤の意匠を持つ。この天秤は**エンディング（story.md「傾き続けた天秤が、ぴたりと水平で止まった」）と対応する、最重要のビジュアル要素**――HPが削れるほど傾き、撃破後に水平へ戻って締めくくる。

| フェーズ | HP | 装甲・輪郭 | 天秤の傾き | 刻印・核 |
|---|---|---|---|---|
| フェーズ1 | 100〜66%超（上層） | 装甲が揃い、左右対称。ひび割れなし | 水平（0°） | 刻印は淡く均等に発光。核は見えない |
| フェーズ2 | 66〜33%超（中層） | 装甲の一部が剥離し、光/闇それぞれの色のページ状破片が舞い始める | わずかに傾く（目安10〜15°） | 刻印の発光にムラが出始める |
| フェーズ3 | 33〜0%超（下層） | 装甲の大部分が失われ、内部の**核**（光と闇が滲むように混ざり合う発光体）が露出。全身が小刻みに震える（明滅・軽微な形状の歪み） | 大きく傾いたまま戻らない（目安30〜45°） | 刻印が裂けて光が漏れる（紅亡霊の亀裂に近い表現だが、ボス固有の規模） |
| **断末魔**（HP≤0の瞬間） | ― | **崩壊しかかっている**：残った装甲が一斉に浮き上がり剥離しはじめ、輪郭そのものが粒子状に分解されかける。既存の暴発の視覚言語（光と闇が混ざった白紫の光）を、ボスの体格に合わせて大きく使い、3つの綻びが体の中心・左右から同時に開く | 制御を失ったように激しく揺れる（固定角なし、演出としてランダムに振れる） | 核が全開放、体全体が発光 |

**撃破後の最終崩壊アニメーション**：
1. 3つの綻びが静まり、震えが止まる。
2. 残っていた装甲・破片が、重力に従うようにゆっくり落下し、崩落後の下層の瓦礫に積もる。
3. 体の輪郭が光の粒子となってほどけ、立ちのぼって消えていく（ゴーレム種族の崩れ方・05c §6.5に近いが、範囲・時間ともに大きく引き伸ばす）。
4. 最後に**天秤の意匠だけが宙に残り、ゆっくりと水平に戻ってから消える**――story.md「STAGE_CLEAR[7]」の描写と完全に対応させる、演出の締め。

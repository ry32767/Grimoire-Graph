# 11. ステージエディタ（開発者用ツール）

> 壁配置・ステージスケール・敵配置を視覚的に編集し、その場でテストプレイできる**開発者専用**ツール。01-overview.md の「DEV ステージ直行（`?stage=N`）」と同じ位置づけで、**開発ビルドのみで有効・本番ビルドでは無効**。プレイヤー向け機能ではないため、タイトル画面や通常のゲームフローには一切表示されない。
>
> 注：仕様の章番号は元資料では「07」だったが、docs/07 は 07-animation.md が占めるため本リポジトリでは 11 番に採番する。

---

## 1. 目的

- 06b-difficulty-framework.md の壁配置や敵配置を、**座標を手計算せずに視覚的に組み立てる**。これまでの壁配置図（`diagrams/stage{N}-walls.svg`）は静的な参考図だったが、本ツールは**実際にその場で動かして確認できる**動的な版にあたる。
- 実プレイで見つかった不具合（例：座標ミスに起因する回り込み）のような問題を**実装前に開発者自身が気づけるようにする**。
- ステージ定義（`stages.ts` の `enemy()`/`pillar()`/`block()`/`wall()`/`colonnade()`/`spiralArm()`/`ring()`/`roomWalls()`/`roomWallsOpenEnds()` 呼び出し）と1:1で対応するデータ構造を編集する。エディタ独自のスキーマは持たない。

> 補足（部屋モデル・翼壁廃止）：現行の壁配置は「円の中に壁で囲った部屋」（`roomWalls`/`roomWallsOpenEnds`）に移行し、翼壁（`wingWall`）は廃止した（06b §5.6 参照）。§4.4 の「翼壁プリセット」は、現行コードに合わせて「**部屋の囲い（roomWalls）を自動追加**」プリセットとして実装する。

---

## 2. アクセスと権限

- **開発ビルドのみ**（`import.meta.env.DEV` 相当の判定）。本番ビルドでは該当コード自体が含まれない、または起動しない。
- アクセス経路：タイトル画面の開発者専用ボタン（01-overview.md の「DEV ステージ直行」ボタン群と同じ並びに追加）、または `?editor=1` のようなクエリパラメータ。
- 本番ビルド・エンドユーザーには一切露出しない。

## 3. 画面構成

```
┌─────────────────────────────────────────┬───────────────┐
│                                           │ ステージ設定   │
│                                           │ ・LVL          │
│              編集キャンバス               │ ・rField(規模) │
│         （BattleCanvas を流用）           │ ・mechanics    │
│   ・場の境界（rField）を円で表示          ├───────────────┤
│   ・味方（ドラッグ可）                    │ 選択中オブジェクト│
│   ・敵（ドラッグ可・パターン別アイコン）  │ の詳細フォーム  │
│   ・障害物（ドラッグ・数値編集）          ├───────────────┤
│                                           │ ＋敵を追加     │
│                                           │ ＋壁を追加     │
│                                           │ （種別選択）   │
├───────────────────────────────────────────┼───────────────┤
│ [テストプレイ]  [リセット]  [書き出し]    │               │
└─────────────────────────────────────────┴───────────────┘
```

- **キャンバス描画は本編の`BattleCanvas`/`draw.ts`をそのまま流用**する。エディタ専用の別レンダラーは作らない――見た目のズレ（仕様書の図と実装の見た目が食い違う）を根本から防ぐため。
- **座標変換も本編の`coords.ts`を流用**。クリック・ドラッグ位置とゲーム座標の対応がずれない。

## 4. 壁配置の編集

### 4.1 追加

「＋壁を追加」から、既存の障害物ヘルパー（04-magic §4.4・06-stages.md ヘッダ）を種別選択で呼び出す。

| ヘルパー | 編集項目 |
|---|---|
| `disc(cx, cy, r, element, kind)` | **任意半径の円（柱）1個**（#68・自由配置）：中心座標、半径、属性、種別 |
| `rect(x, y, w, h, element, kind)` | **任意サイズの矩形の壁1枚**（#68・自由な部屋）：左下座標、幅、高さ、属性、種別 |
| `pillar(cx, y0, n, element, kind)` | 中心x、開始y、段数n、属性、種別 |
| `block(x0, y0, cols, rows, element, kind)` | 開始座標、列数、行数、属性、種別 |
| `wall(x0, x1, y0, rows, element, kind)` | 始点x、終点x、開始y、段数、属性、種別 |
| `colonnade(x0, x1, step, y0, n, elems[])` | 始点x、終点x、柱間隔、開始y、段数、属性配列（順に割当） |
| `ring(cx, cy, radius, element, kind)` | 中心座標、半径、属性、種別 |
| `roomWalls(xL, xR, yB, yT, rField, element, kind)` | 部屋の左右上下、属性、種別（既定値 neutral/unbreakable） |
| `roomWallsOpenEnds(xL, xR, rField)` | 部屋の左右（属性・種別は固定＝neutral/unbreakable） |
| `spiralArm(cx, cy, n, turns, phase, element)` | 中心座標、点数、巻き数、位相、属性（雰囲気演出用・当たり判定あり） |

種別（`kind`）は `normal`/`fragile`/`tough`/`unbreakable`（04-magic §4.4）から選択。

### 4.2 プレビューと当たり判定の可視化

- パラメータを変更するたびに、キャンバス上の**実際の円（`solids`の構成円）・矩形（`rects`）**をリアルタイムに再描画する（本編と同じ個々の素材を正確に描く）。
- 複数の障害物が重なっている箇所は、警告色でハイライトする（意図しない重なりを即座に発見できるようにする）。

### 4.3 ドラッグ・数値編集

- 既存の障害物をキャンバス上でドラッグすると、対応するヘルパーの基準座標（`x0,y0`など）がその移動量ぶん更新される。
- 右側の詳細フォームから、各パラメータを直接数値入力でも編集できる（ドラッグは大まかな配置、数値入力は最終調整に使う想定）。

### 4.4 部屋の囲いプリセット（旧・翼壁／#50対応）

- 右側パネルの壁一覧の下に「部屋の囲いを追加」ボタン（四方／左右のみ）を用意する。押すと、現在の`rField`に合わせて `roomWalls`（または左右のみの `roomWallsOpenEnds`）を生成し、四方（または左右）を`unbreakable`で囲う（06b §5.6 の設計をワンクリックで適用）。
- 生成後のパラメータは通常どおり編集・微調整できる（自動生成は出発点であり、確定値ではない）。

## 5. ステージスケールの編集

- `rField`（場の境界半径）を数値入力またはスライダーで変更できる。
- 変更すると、キャンバス上の境界円が即座に再描画される。
- 現在の`LVL`に対する06b §5.5の推奨スケール（`rFieldForSize`）を、入力欄の横に**目安として表示**する（強制はしない）。
- スケールを縮小した結果、既存の敵・障害物が境界の外に出てしまう場合は、該当オブジェクトを警告色で示す（配置の破綻を事前に検知）。

## 6. 敵配置の編集

### 6.1 追加

「＋敵を追加」で、まず**種族・系統**（05c-bestiary.md §0〜§4）を選ぶ：

- 原型／鋼鬼（火力型）／亡霊魔術師（迂回型）／紅亡霊（暴発型）／ゴーレム（守護型）

続けて**ティア**を選ぶと、05cのティア表から HP・family・z場の初期値が自動で入力される（そのまま採用も、上書きも可能）。

### 6.2 詳細フォーム

| 項目 | 対応 |
|---|---|
| 固有名詞 | 表示名（自由入力、05cの命名と揃える） |
| 位置 (x,y) | ドラッグ、または数値入力 |
| LVL | 06b §2〜§4 の解放表に応じて、使える`family`/`z場`/パターンの選択肢が絞り込まれる |
| pattern（役割） | `attacker`/`breaker`/`guardian`/`ruptor`（05-enemies §5.3）＋パターン別の追加設定（例：`ruptor`なら狙う対象の優先度、`guardian`なら光/闇どちらのオーラか・交互張りの有無） |
| family / families[] | 05b §2 の許可表に基づき選択肢が制限される（例：迂回型・暴発型は`abs`/`arc`/`poly34`のみ） |
| z場 | プリセット（一定／sin・cos／指数／方向づけ／極）から選択、または自由入力式 |
| HP / hitboxRadius | 数値入力（05cのティア値が初期値） |
| castInitialSpeed | 表示のみ（06b §2 により全敵・全LVLで固定＝8。編集不可。例外は第6面崩し手=6.5） |

- **自由入力式の評価は mathjs のみ**（graph_mage-spec.md の安全性原則を編集ツールでも継続する。`eval`/`new Function`は使わない）。

### 6.3 多重詠唱（ボス）の編集

- ボス的な敵には「多重詠唱を有効にする」チェックを用意し、有効にすると：
  - `castCount`（同時発射数）をHP割合ごとに設定できる表（05b §5.5・06b 第7面のフェーズ表と同じ形式）。
  - 各`castCount`枠に許可するパターンのプールを選択（例：[火力型, 迂回型]）。
  - 断末魔（HP≤0時の固定演出）を有効にするか、内容（暴発本数・パターン）を個別に設定できる。

### 6.4 味方位置の編集

- 通常は`party.ts`の既定位置が使われるが、エディタでは**テスト目的で味方位置も動かせる**（例：第4面の包囲構成のような特殊配置を試す）。
- 「既定位置に戻す」ボタンを用意し、いつでも`party.ts`の値に戻せるようにする。

## 7. テストプレイ

- 「テストプレイ」ボタンで、**現在編集中のステージ定義をそのまま使って戦闘を開始**する。タイトル・序章・ステージ導入はすべて飛ばし、直接`battle`フェーズへ入る。
- 開始時のパーティHPは全快。**`instability`（膜メーター）の初期値をデバッグ用に指定できる**（例：終盤の危険な状態を再現してテストしたい場合に、`instability=10`から始める、など）。
- テストプレイ中の状態（HP消費・`instability`の増減など）は、**エディタの編集内容やその他の実行中の状態と完全に分離**する（本編の進行状況に影響を与えない。本ゲームは永続化なしのため「このタブでのテストプレイ用の使い捨てセッション」という扱い）。
- テストプレイを終了（勝利・敗北・中断のいずれか）すると、**編集画面にそのまま戻る**（タイトルには戻らない）。細部を直してすぐ再テスト、のループを繰り返しやすくする。

---

## 8. リセット

- 「リセット」ボタンで、現在の編集内容を**直近の基準状態**（既存ステージNを開いて編集を始めた場合はそのステージの元定義、新規作成の場合は空のテンプレート）に戻す。
- 破壊的な操作のため、実行前に簡易確認（インライン確認・モーダルは使わない軽量な確認で十分）を挟む。
- 個別の要素（1つの壁、1体の敵）だけを削除する操作とは別の機能（リセットは全体の巻き戻し、削除は個別の除去）。

---

## 9. 書き出し（エクスポート）

- 本ゲームはDB・永続化を持たない方針（01-overview.md）のため、エディタの編集内容もブラウザを閉じれば消える。**成果を持ち出す手段として書き出し機能を用意する**：
  - 現在のステージ定義を、`stages.ts`にそのまま貼り付けられる**TSコード片**として生成し、クリップボードにコピーできる（`enemy()`/`pillar()`/`block()`/`wall()`/`colonnade()`/`spiralArm()`/`ring()`/`roomWalls()`の呼び出し列として出力）。
  - 併せてJSON形式でのコピーも用意する（他ツールでの二次利用や差分確認用）。
- 書き出しはあくまで「開発者が手作業でソースに反映する」ための補助であり、エディタから直接ファイルを書き換える機能は持たない（スコープ外）。

## 10. 受け入れ条件

- [x] エディタは開発ビルドでのみ到達可能で、本番ビルドには含まれない／表示されない（`import.meta.env.DEV`・`App.tsx` でのみマウント）
- [x] キャンバス描画・座標変換は本編の`draw.ts`/`coords.ts`を流用し、エディタ専用の別実装を持たない（`BattleCanvas`を流用）
- [x] 壁（`pillar`/`block`/`wall`/`colonnade`/`spiralArm`/`ring`/`roomWalls`/`roomWallsOpenEnds`）を追加・編集・削除でき、パラメータ変更が実際の当たり判定素材としてリアルタイムに反映される（`ObstaclePanel`・`opEditing.ts`）
- [x] 障害物どうしの意図しない重なりが、キャンバス上で警告表示される（`ObstacleOverlay`・`overlap.ts`）
- [x] 選択中の壁に「部屋の囲いを自動追加」を適用すると、現行の`roomWalls`/`roomWallsOpenEnds`（`unbreakable`）が生成される（`roomPresetOp`・`opEditing.ts` §118〜129）
- [x] `rField`を編集すると境界円が即時更新され、境界外に出たオブジェクトが警告表示される（`StageEditor` §125〜134）
- [x] 敵の追加時、種族・ティア選択に応じて05cの初期値（HP/family/z場）が自動入力され、以後上書きできる（`EnemyPanel`/`enemyTiers.ts`）
- [x] 敵のfamily/z場選択肢は、選んだLVL・パターンに応じて05b §2の許可表どおりに制限される（`enemyRules.allowedFamilies`/`allowedZFields`・`enemyRules.test.ts`）
- [x] 自由入力の式評価はmathjsのみで行われる（`eval`/`new Function`不使用。`src/game/functions.ts`の`parseZExpression`を再利用）
- [x] 多重詠唱・断末魔を持つボスの設定（castCount・パターンプール・HP閾値）を編集できる（`EnemyBossSection`・`BossPhasesPanel`。断末魔自体はengine側の固定演出のため内容編集は対象外）
- [x] 「テストプレイ」で編集中の定義のまま戦闘が開始し、`instability`の初期値を指定できる。終了後はエディタ画面に戻る（`App.startTestPlay`/`endTestPlay`・本編の進行状況とはスナップショットで分離）
- [x] 「リセット」で編集内容が基準状態に巻き戻る（確認を挟む）（`StageEditor.handleReset`・インライン確認）
- [x] 「書き出し」で、`stages.ts`に貼り付け可能なTSコード片が生成される（`exportStage.exportToTS`・JSON版`exportToJSON`も併設。`ExportBar`でクリップボードコピー）

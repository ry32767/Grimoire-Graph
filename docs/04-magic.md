# 04. 魔法（二系統・暴発・パリィ・障害物・結界）

魔法の挙動を司るモジュール群：
`loop.ts`（系統分類）、`orbit.ts`（結界）、`misfire.ts`（暴発）、`parry.ts`（相殺）、`obstacle.ts`（えぐり半径・速度損）、`carve.ts`（`carveAlong`＝えぐりの解決本体。本番 `turn.ts` と敵AI事前評価 `enemyPlanning/` が共有）、`turn.ts`（解決の統合）。

---

## 4.1 二系統の分類（`src/game/loop.ts`）

軌道が「閉じている（ループ）」かで魔法を 2 系統に分ける。

```ts
classifyTrajectory(traj) = isLoop(traj) ? 'orbit' : 'projectile'
```

### `isLoop` の判定

- **回転方式 `y=g(x)`** … 常に開（`projectile`）。関数グラフは単調に外へ伸びる。
- **極座標方式 `r=f(θ)`** … 場外で切らず有限点で判定：
  1. 有限プレフィックスが 12 点未満 → 開。
  2. 始点からの最大離脱距離 `maxDepart` が 1.5 未満（ほぼ点＝退化）→ 開。
  3. 後半（点列の 50% 以降）のどこかで始点付近（許容 `max(0.6, maxDepart·0.2)`）へ戻れば → **閉（orbit）**。

円・バラ曲線・リマソンは閉じて結界に、らせんは開いて発射型になりやすい。

## 4.2 発射型（projectile・火球）

開いた軌道。術者から飛び、**通過した全対象に命中する（貫通）**。
魔法は**外部からの干渉（z 場の加速度・パリィ/結界相殺・壁）で速度 0 にならない限り効果を失わず**、
**命中しても減速せず消えない**。対象ごとに「その点の速度×強度」の威力分のダメージを与えて飛び続ける。

解決の流れ（`turn.ts` の該当部分）：

1. `simulateFlight` で自由飛行を作る。
2. **障害物を削りながら進む**（§4.4）。途中で速度 0 なら消滅。
3. guardian 敵の防御結界を横切るとパリィと同じ相殺（反対極のみ・同極は透過。§4.5：威力の引き算＝必ず片方消滅）。命中の先の結界とも相互作用する（貫通のため「命中で打ち切り」はない）。
4. `allHitsAmong` で経路上の全ヒットを弧長順に取り、それぞれ `computeDamage` でダメージ＋状態異常（命中で弾は減速しない）。
5. 軌道が `invalid` に達すれば **暴発**（§4.3）。貫通のため**命中と暴発は両立する**（途中で命中しても、エラー点まで届けばそこで暴発する）。命中も暴発もなければ外れ（miss）。

## 4.3 暴発（misfire・`src/game/misfire.ts`）

> **拡張**：暴発の**累積（instability・膜メーター）・半径のばらつき・崩壊イベント**は [04b-misfire-instability.md](04b-misfire-instability.md)。敵が z 場の極で意図的に暴発を起こす**崩し手（ruptor）**は [05-enemies.md](05-enemies.md) §5.4b。敵の暴発も味方と同じこの仕様で解決される（威力・AoE・壁の削り・結界の削り・状態異常）。

関数がエラー（未定義・発散・非実数・`1/x` の極など）になった点で魔法が綻び、**光と闇を最大強度で併せ持つ大 AoE** が起きる。

```ts
power  = sMax(=5) × maxFlightSpeed(=24) = 120       // 常に最大（速度に依らない・#41）
damage = power × AFFINITY.opposite(=1.5) = 180      // 常に有利側
AoE 半径 = aoeRadius(=5)
状態異常 = maxStatuses()                            // 光ひるみ＋闇DoT を最大強度で両方
```

- **威力は常に最大**（`sMax × maxFlightSpeed`）。暴発時の速度に依らず一定で、光・闇の両属性を最大強度で帯びる（#41）。
- AoE 内の**生存している**敵全員＋暴発点 `aoeRadius` 以内の生存味方全員にダメージ＋状態異常（撃破済み hp0 は対象外＝判定を出さない）。
- **AoE 内の壁もほぼ全て削れる**（#41）：暴発点を中心に `aoeRadius` ぶんの円を `carves` に足し、範囲内の素材を丸ごと除去する。`unbreakable`（壊れない壁）だけは残る。砕けた各 disc 位置で破片バーストが舞う。
- **AoE 内の結界（周回リング）も最大威力でパリィ相当に削る**（`blastOrbits`）：削り量はパリィと同じ `威力 × parryLossScale`（威力は常に最大 `sMax × maxFlightSpeed`）。AoE 内で最も速いリング点の速度から差し引き、残れば全体を同率で `scaleRingSpeeds`、速度0で霧散。暴発は光闇両極を最大で帯びるため**相手属性に関係なく必ず作用**し、**味方・敵どちらの結界も**（新規リング・持続結界とも）削る。`maxFlightSpeed(24)` を超えるリング速度は存在せず、削り量（`120×0.25=30`）がそれを上回るため、実際に AoE へ触れた結界はほぼ確実に霧散する。
- **効果中に AoE 圏内へ入った飛行中の弾も呑む**（#66・`turn.ts` §4.7）：爆発の瞬間（暴発弾がその弾の飛行時間で暴発点へ達する時刻）から `misfireBlastTime(=1.5 ゲーム秒)` の間に、AoE 圏内に入った（または居た）**発射魔法**は、結界と同じ最大威力のパリィ相当減速（`120 × parryLossScale = 30`）を受ける。`maxFlightSpeed(24)` を上回る削り量のため、実際に呑まれた弾はその場で消滅する。敵味方無差別・両極なので属性を問わず作用する。**爆発より先に AoE を通過し終えた弾は影響を受けない**（両者の飛行時間＝Σds/v で判定）。同一ターンに複数暴発する弾どうしは同時扱いで互いに干渉しない。AoE の実半径（instability のばらつき込み・04b §4b.3）はこの判定と §5/§6b のダメージ解決で同一の値を使う。
- 暴発点が術者近傍なら**自爆**（`selfHit`）。足元で関数が壊れると味方を巻き込むので注意（自爆判定は術者＝発射元の位置基準）。
- `detectMisfire` は `pathTermination` を使い、`maxParam`（場内で完結）なら暴発しない。
- **z 場（属性関数）のエラーでも暴発する**（#30）。`sqrt(-1)`・`log(0)`・`1/x` の極など、**軌道は有効でも z 場が経路上でエラー（非有限）になる点**で同じ暴発が起きる（検出は `coords.ts` の `applyZValidity`・[03-functions.md](03-functions.md) §3.3）。暴発点はエラー手前の場内有効点。
- ステージ 6 のヒントにある通り「狙って暴発させて最大 AoE を当てる」高等戦術も成立する。

### プレビューでのエラー可視化（#30）

作成フェーズのプレビューで、関数エラーを 2 通りに可視化する：

1. **弾の暴発点（赤い ✕）**：軌道・z 場のどちらかがエラーで、弾が実際に暴発する点。`draw.ts` `drawMisfireMarker`。`computePreview` が `detectMisfire` の結果（`type==='invalid'` のみ）を `Preview.misfirePos` として返し、`App.tsx` → `BattleCanvas`（`misfirePoints` prop）→ `drawScene` の最前面に描く。場外脱出（ただの外れ）には出さない。各味方ぶん表示。
2. **場のエラー地点を全て（赤い線/領域）**：作成フェーズ中（`showZField`＝常時・#55）、アクティブな術者の z 場が**エラーになる地点を全て**赤で重ねる（`draw.ts` `drawZFieldErrors`）。
   - **非有限**（`sqrt(-1)`・`log(0)` などの定義域外）→ 赤い**領域**。
   - **極（発散・`1/x` 型）** → 赤い**線**。場を `step=0.8` で走査し、符号反転する隣接点を二分法（`isPoleBetween`）で調べ、寄せるほど \|z\| が際限なく増大（非有限 or `ERR_BLOWUP=500` 超え）すれば極と判定する。連続関数の零点（\|z\|→0 に収束）と区別でき、急峻でも有界な場は誤検出しない。

①は「弾がどこで暴発するか」、②は「場のどこが危険か（全エラー地点）」を示す。撃つ前に式の破綻箇所を確認できる。

## 4.4 障害物のえぐり取り（`src/game/obstacle.ts`・Graph War 風）

障害物は耐久値を持たず、形は `solids`（重なった円の和＝連続ブロブ）で表す。
**魔法が当たった点を中心に円 `carves` を引き算して物理的にえぐる**。素材＝「どれかの solid 円内 ＆ どの carve 円にも入らない点」。

### 素材判定

```ts
isSolidAt(ob, p) = (どれかの solid 円内) かつ (どの carve 円にも入らない)
```

### えぐり半径（`carveRadius`）

```ts
base = min(carveMaxRadius(=2), max(0, power) × carveRadiusScale(=0.05))
半径 = base × OBSTACLE_KIND[kind].carveScale
```

威力 `power = 速度 ×(強度+1)`（中立弾でも運動量で少し掘れる）。威力が高いほど一撃で広く削れて貫通しやすい。

### えぐりの速度損（`carveSpeedLoss`）

```ts
損 = carveCost(=7) × (2 − 相性) × OBSTACLE_KIND[kind].lossScale
```

相性 1.5(反対極)→×0.5、1.0(中立)→×1、0.5(同極)→×1.5。**反対極ほど安く削れて貫通しやすい**。
速度が 0 になればその場で消滅し貫通しない（目安：最大威力で柱 1 本を約 3 発）。

### 壁の耐久種別（#40・`OBSTACLE_KIND`）

| 種別 | carveScale（半径） | lossScale（速度損） | 挙動 |
|---|---|---|---|
| `normal` | 1 | 1 | 従来の属性付き壁。light/dark で相性が効く。 |
| `fragile` | 1.7 | 0.55 | 無属性・もろい。一撃で大きく崩れる。 |
| `tough` | 0.32 | 1.7 | 無属性・頑丈。最大火力でも貫通に複数発。 |
| `unbreakable` | 0（削れない） | 1 | 壊れない。当たった魔法は**その場で全速度を失い停止**（迂回必須）。 |

実装の細部（`src/game/carve.ts` の `carveAlong`）：飛行サンプルは軌道頂点なので、急な関数では頂点間が開く。`OBSTACLE_STEP=0.6`（`src/data/constants.ts`）以下に密化（`densifyGeom`）して壁のすり抜けを防ぐ。`unbreakable` に当たると全速度損で停止。本番の解決（`turn.ts`）と敵AIの事前評価（`src/game/enemyPlanning/evaluate.ts`）は `carve.ts` の同一実装を共有する（判定不一致＝壁埋まりの根絶）。

- **削りの打ち切り＝「壁の中で止まった」ときだけ（バグ修正・#64）**：削りごとの再シミュレートで `flight.end==='vanished'` になっても、**消滅点（最終サンプルの弧長）が現在の削り位置以前のときだけ**「壁止まり（`vanished`）」として打ち切る。消滅点がもっと先（z 減速による自然失速点など）なら弾はまだこの素材点を通過できるので削り続ける。従来は消滅した時点で無条件に打ち切っていたため、遠くで失速するだけの弾が壁を数回しか削らず**残りの素材の中を素通りして見える**（アニメ上だけ貫通する）バグがあった。現在は弾は壁の中で本当に止まる。素材への接触が尽きた後でも、削りの減速で消滅点が「最後に削った素材の位置以前」まで手前に来ていれば同じく壁止まりと判定する。

> 敵弾も同じ仕組みで障害物に削られる（障害物は味方の盾にもなる・#16）。敵弾の `blocked`（以降の迎撃・干渉を打ち切る）は**壁の中で止まった（`carveAlong` の `vanished`）ときだけ**（#64）。ただし**命中は blocked でも打ち切らない**（spec §9 の決定）：飛行サンプルは停止点（壁止まり・パリィ消滅・自然失速のいずれも）で打ち切られるため、**停止点より手前で通過した味方への命中は常に有効**。味方弾（§5 相当）と同じ扱いで、AI の事前評価（届く威力の採点）とも一致する。

## 4.5 パリィ（相殺・`src/game/parry.ts`）

弾／結界が交差したときの共通解決。**同極・中立はすり抜け、反対極のみ相殺**。結界の迎撃（§4.6）も、交差する一点でリングを「その点の属性・リング速度の弾」と見なし、この同じ `resolveParry` で解く（#59）。

```ts
bulletCollision(samplesA, samplesB, radiusA, radiusB)  // 発射型どうしの実衝突点＋時刻（#64/#72・下記）
firstCrossing(pathA, pathB)  // 最初の交差点（線分交差）。敵AIの粗い絞り込み・プレビュー表示のみ
resolveParry(attrA, speedA, powerA, attrB, speedB, powerB):
  反対極でなければ → passthrough（速度そのまま継続）
  反対極なら:  // 威力の引き算：必ずどちらか（同威力なら両方）が消滅する
    powerA > powerB → A が勝ち：newA = speedA × (powerA − powerB) / powerA、B は消滅
    powerB > powerA → B が勝ち：newB = speedB × (powerB − powerA) / powerB、A は消滅
    powerA = powerB → 完全相殺で両方消滅
```

- **威力の引き算**：互いの威力（速度×強度）を引き算し、**大きかった側だけが残威力 `powerWin − powerLose` を引き継いで継続**する。強度は位置で決まるため、残威力は速度の縮小（`speed × 残威力/元威力`）として反映する。**パリィが発生したら必ずどちらかは消滅する**（結界の迎撃・相殺も同様）。勝った側の減速は `turn.ts` §3b で `pLosses`／敵弾の減衰イベントへ積み、以後の交差・命中・障害物へ引き継ぐ。
- **実衝突判定（#64/#72・`bulletCollision`）**：発射型どうしのパリィは、経路が幾何的に交差するかではなく「**同じゲーム時刻に本当にぶつかるか**」で判定する。各弾の飛行サンプル列から各点への到達時刻（`flightTimes`＝Σ ds/v・区間平均速度の台形積分。失速区間から先は ∞）を作り、**両弾を同一時刻 τ で `FIELD.dt`(=1/60秒) ずつ時間行進**させ、中心間距離が **互いの当たり半径の和 `bulletRadius(A) + bulletRadius(B)`**（＝画面に描かれるコア半径の和・[02-calculations.md](02-calculations.md)）以下へ近づいた**最初の点**（両弾位置の中点）を衝突点とし、その τ を衝突時刻として返す。正面撃ち返し（同一直線の逆走）は途中の合流点で**必ず成立**し、経路が交わるだけのすれ違い（通過時刻に差がある）は**自然に不成立**。どちらかが消えた（終端・失速）後は衝突しない。旧方式（幾何交点 `firstCrossing`＋通過時刻ゲート `parrySyncDist`）は、正面撃ち返しでも最初の交点の時刻差で弾かれ「パリィがほぼ成立しない」不具合があったため置き換えた。
- **弾も結界も1つの時系列で解決（#72）**：全（敵弾×自弾）の実衝突と全（弾×反対陣営の結界）の接触（§4.6 `ringContact`）を洗い出し、**ゲーム時刻の早いものから**1件ずつ解決する（`turn.ts` §3b）。1件解決するごとに影響した飛行を再シミュレートして残りを再計算する。**勝ち残った弾は残威力で飛び続け、別の魔法・結界と再び干渉しうる**。同じペアは最初の接触1回だけ判定する（同極・中立はその点ですり抜け確定）。旧実装は結界の迎撃を幾何交差でパリィより先に全部解いていたため、**先に相殺されて消えたはずの弾が後方の結界を壊す**因果の逆転が起きていた。
- クラッシュ火花の威力は 2 魔法の威力合計（#38）。

## 4.6 軌道型＝結界（orbit・`src/game/orbit.ts`）

閉じた軌道。術者の周りを回り、**掃射（攻撃）＋迎撃（防御）＋属性オーラ（回復/隠蔽）**を兼ねる。

### リング構築（`buildRing`）

`validFinitePrefix`（場外でも切らない）で 1 周分（θ ≤ 2π）の点列＋各点の z を作る。2 周分にしないのは演出が倍速・粒子重複になるため（#22）。

### リング速度は点ごと（#60）

リングの速度は**平均（代表スカラー）ではなく点ごと**に持つ。`buildRing` で幾何＋z を作り、
`attachRingSpeeds(ring, initialSpeed)` が初速からリング経路を物理シミュレート（場の加速度で加減速）して
**各点の速度 `RingPoint.speed`／`ZPoint.speed` を付与**する。中立帯は速く、強属性(|z|>zRef)の点は失速する。
迎撃・掃射・演出はすべて「その点の速度」を使う。速度0まで失速した点以降は0。

### 掃射（攻撃・`orbitSweep`）

リング上で対象に最も近い点との距離が `半径 + orbitSweepReach(=0.7)` 以下なら命中。

```ts
ダメージ = 触れた点のリング速度(ring[idx].speed) × strengthOf(その点の z) × 相性   // #60：平均でなく点ごと
```

命中時、対象に属性に応じた状態異常も付与。

### 迎撃（防御・`ringContact` ＋ パリィ・#59/#72）

弾が**リングの帯に触れた最初の時刻**（時間刻み・`FIELD.dt`）に着目し、リングを「その点の属性・リング速度の弾」と見なして
発射魔法のパリィ（§4.5 `resolveParry`）と**同じ相互相殺**で解く。**反対極のみ相殺、同極・中立は透過**。
結界は静止した閉曲線なので動くのは弾だけ（リング点の速度は威力にのみ効く）が、
**接触の「時刻」がパリィ・暴発と同じ時間軸に乗る**ことが重要（時系列順に解決するため・§4.5）。

```ts
c = ringContact(ring, samples, radiusAt)   // 接触点・時刻・その点のリング z / 速度(#60)
   // 接触条件：dist(弾の中心, 最寄りのリング点) ≤ bulletRadius(速度, z) + orbitBandHalf(=0.35)
vCross = c.ringSpeed                        // 接触点でのリング速度（平均でない・#60）
parry = resolveParry(ringAttr, vCross, vCross×strengthOf(ringZ),
                     enemyAttr, c.speed, c.speed×strengthOf(enemyZ))
結界の勝ち（リング威力 > 弾威力）: 弾は横断点で消滅。結界は残威力ぶんの減速率
    factor = parry.speedA / vCross で全体を失速して回り続ける
弾の勝ち（弾威力 > リング威力）: 結界は破れて丸ごと霧散。弾は残威力
    （before − parry.speedB を削った速度）で継続する
同威力: 完全相殺で両方消滅
```

- **威力の引き算・必ず片方消滅**：発射魔法のパリィ（§4.5）と同一の `resolveParry`。**相殺が起きたら弾か結界のどちらかは必ず消える**（同威力なら両方）。
- **接触点の速度で相殺（#60）**：迎撃は平均速度でなく**接触した一点の速度 `vCross`** をリング弾の速度に使う。
- **当たりは見た目と一致（#72）**：接触距離は「弾の本体（属性色の円）の半径＋帯の半厚み」。帯は `2×orbitBandHalf` ユニット幅で描かれる（`board.drawOrbitRing`）。
- **勝った結界も減速する（#59/#60）**：迎撃した結界は残威力に応じて失速し、**横断点の減速率 `factor` で結界全体を `scaleRingSpeeds` して**（各点の speed を factor 倍）残った速度で回り続ける。代表 `ringSpeed` も同率で更新し、**次ターンへ減速したまま持ち越す**（前ターンの速度値が次ターンの迎撃力になる）。
- 味方弾が敵 guardian の防御結界（今ターンの新規リング＋持続結界 `owner='enemy'`）に触れる場合も同じ相殺で解く（`turn.ts` §3b の同じ時系列に載る。命中しない弾が触れても結界は減速・破壊され、自弾の減速は以後の命中・霧散判定へ引き継ぐ。貫通のため、敵に命中した先の結界とも相互作用する）。
- **破壊には時刻がつく（#72）**：結界が破れた**ゲーム秒**を `allyShots[].breakTime`／`enemyRings[].breakTime`／`orbitBreaks[id].t` で返す。霧散の演出はこの時刻ちょうどから始まる（暴発 AoE に呑まれた結界も、爆発の時刻で散る）。
- `parryLossScale(=0.25)` はパリィでは使わなくなり、**暴発 AoE の結界/弾削り（§4.3）専用**の係数になった。旧 `orbitBlockLoss`／`orbitBlockScale(0.45)` は廃止。
- クラッシュ威力＝リング威力(強度×横断点速度)＋敵弾威力(速度×強度)（#38）。

### 壁との接触（`orbitWallBreak`）

リングが障害物の素材に触れると、`orbitWallCarveRadius(=0.5)` でほんの少し削り、**周回は丸ごと霧散して消える**（掃射/防御/オーラを失う・#34）。

### 強属性での減速・自滅（#31/#44）

強属性（|z|>zRef）でリングは減速し、**周回速度が 0 に達すると結界も自滅して霧散する**（壁破壊と同じ霧散演出に乗せる・#31）。霧散点に小さな碎け（carve）を残し、ログに「周回結界は強すぎて失速し、自滅して消えた」と出して**自滅したことが分かる**ようにする（#44）。

そのため `zRef`(=2.5) 付近が「減速せず速く＝強いまま回り続ける」安定点になり、最強の |z|=zPeak(=5) を狙うほど早く失速して自滅するという #31 のトレードオフが成り立つ。既定の周回（z=±5）はこの自滅対象なので、結界として使い続けたいときは |z|≤zRef に乗せる。

> 自滅（失速）と「敵弾に破られて霧散」は別物。前者は敵弾なしでリングがその場で散り、後者は反対極の敵弾が貫いた点で散る（ログ文で判別できる・#44）。

### 破壊点の記録と霧散演出の同期（#64）

結界が破壊されたとき、`resolveTurn` は**破壊点**を結果に記録する：敵 guardian の新規リングは `ResolveResult.enemyRings[].breakPos`、持続結界（`activeOrbits`）は `ResolveResult.orbitBreaks`（破壊された結界 id → 破壊点の Record）。破壊点は迎撃・パリィの交差点、暴発 AoE の接触点、壁接触点（`orbitWallBreak`）、失速自滅の最終サンプル位置など破壊要因ごとに入る。`App.tsx` がこれを `AnimOrbit.carves` の同期点として渡し、`BattleCanvas` の霧散演出は「**弾がその点へ到達した瞬間**」から散り始める（従来はアニメ窓の 40% 固定時刻で開始しており、弾の到達とズレていた）。ロジック（速度・破壊判定）は不変で、演出タイミングのみの同期。

### 属性オーラ（内側への効果・#35/#39/#61）

リングが囲んだ**味方（自陣結界）／敵（敵 guardian 結界・#61）**に、**毎ターン**効果を及ぼす。属性は軌道上の符号付き強度の平均（`ringAverageAttr`）で決まり、効果は強度の大小を見ない固定量。入れ子は**内側（半径が小さい）優先で最大 2 つ**だけ効く。

| リング属性 | 自陣結界の効果（対 味方） | 敵 guardian 結界の効果（#61） |
|---|---|---|
| **光** | 味方を毎ターン固定回復 `orbitHealAmount = 30`（重複可・1 重ごと） | 内側の**敵を毎ターン固定回復**（同じ 30）。内側に「癒やしの輪」（昇る光の粒）を描き、2枚重なった範囲は明るく塗って「二重回復」を示す（`board.drawLightAura`・#73） |
| **闇** | 味方を隠蔽（敵の狙いがずれる）。`orbitConcealFull(=2)` 重で完全に視認不可。RMSE は半径連動（1 重=半径/2、2 重=半径） | **プレイヤーへの視認阻害**：結界が残っている間、その範囲に**闇の幕＋粗いドットのざらつき**がかかり、z 場の同心円も予測経路も読めなくなる（`drawDarkVeil`）。さらに **1 重では隠された単位の分身が半径 `rmse` の円周に散る**（`drawConcealDecoys`・#73）＝「座標がこれだけぶれる」が目で分かる。**2枚が重なった領域は濃い靄で完全に見えない＝「視認不能」**（#62/#73） |

> 敵 guardian の結界は `owner='enemy'` の持続結界（`ActiveOrbit`）として残り（#61）、作成フェーズで `standingOrbits` として表示される。闇の敵結界は数値効果を持たず、視認阻害は**描画側**（`BattleCanvas` が `board.drawDarkVeil`：闇の幕＋5px 市松のドットで z 場・予測経路を隠す＝**1枚はギリギリ見える**、**2枚の重なりは交差クリップで完全な黒＋「視認不能」＝全く見えない**（#62）。境界は流れる破線と見出しで示す）で表現する。光の敵結界は敵を回復する。
>
> **持続する敵結界の処理（バグ修正）**：`turn.ts` は今ターン新規に張った敵結界（`enemyRings`）と前ターンから持続する `owner='enemy'` の `activeOrbits` を**同一の敵結界リスト（`enemyGuardRings`）に束ねて**扱う。これにより、guardian がひるみ／`fireEvery` で沈黙して再詠唱しないターンでも、持続結界が (1) 味方弾を迎撃・減速し（§5 の発射型命中前処理）、(2) 光なら内側の敵を回復させ（§5.5 の敵オーラ）、(3) 相殺されなければ次ターンへ持ち越される（存続判定は**所有者が生存する敵か**で行う）。修正前は持続する敵結界が毎ターン脱落し、沈黙ターンに guardian が無防備になっていた（第3面の広間の番兵〔directed〕／第4面の封印の番人〔alternating〕で顕在化）。

### 永続化（#39・`ActiveOrbit`）

一度張った結界は**破壊されるまでターンをまたいで残る**。

- 毎ターン内側へ効果（回復/隠蔽）を及ぼし、敵弾を迎撃する。
- 反対属性の弾に相殺されると消える。所有者（術者）が倒れても消える。
- 安定 ID（所有者＋リング重心＋点数）で管理し、同じ場所への張り直しは同一 ID に集約。

> guardian 敵も同じ結界の仕組みで防御リングを張る（[05-enemies.md](05-enemies.md)）。

## 4.7 解決順序（`resolveTurn`）まとめ

1 ターンの同時発射はこの順で解決される（詳細は [09-data-model.md](09-data-model.md)）：

```
1. 敵弾を構築（guardian は防御リングへ分離）
2. 味方発射を分類・構築（軌道型は壁接触で霧散。強属性で失速し速度0なら自滅して霧散・#31/#44）
3. 防御：障害物が敵弾を削る → 軌道型リングの迎撃（威力の引き算・必ず片方消滅）
   → 発射型のパリィ（全ペアの実衝突をゲーム時刻の早い順に解決。勝ち残りは多段パリィしうる）
4. 障害物：味方の発射型を削りながら遮る（パリィで受けた自弾の減速を引き継ぐ・#59）
5. 攻撃：命中（発射型・貫通で経路上の全敵に命中し減速しない。敵 guardian 結界とはパリィ同様の相殺）
   ／掃射（軌道型）／暴発（貫通のため命中と両立する）
5.5 周回の属性オーラ（回復/隠蔽）を内側の味方へ
6. 敵弾が味方へ命中（貫通：経路上の全味方に命中）
（最後に）永続周回を更新して次ターンへ持ち越し（結界は減速した速度値のまま持ち越す）
```
</content>

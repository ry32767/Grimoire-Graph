# 07. アニメーション・描画・音

解決演出は `src/components/BattleCanvas.tsx`（タイムライン駆動）、盤面そのものの見せ方は
`src/render/board.ts`（DC プロトタイプ v3 の盤面プリミティブ）、スプライト・エフェクトは
`src/render/draw.ts`、配色は `src/render/theme.ts`、効果音/BGM は `src/audio/sound.ts`。

Canvas は**盤面コンテナ全面**（`.gm-board-inner` の実寸）を占める。`ResizeObserver` で CSS ピクセルの
実寸を測り、内部解像度は `devicePixelRatio`（最大 2）倍、`ctx.setTransform(dpr,0,0,dpr,0,0)` で
**描画は常に CSS ピクセル座標**で行う（`imageSmoothingEnabled=false`）。
ビューポートは `{width, height, unitsRadius: stage.rField, zoom, pan}`。倍率は
`scaleOf(vp) = min(width,height)/2/unitsRadius × zoom` なので、横長の盤面でも場は中央に真円で収まる。

### 詠唱コンソール（`FunctionPanel` / `ZFieldControls` / `DraftPad`）

術式編集ウィンドウの中身。**y（軌道）と z（属性場）を別入力**として上下に並べ、
**いま編集している側のコントロールだけ**を出す（もう片方は隠す）。

- `y=` 欄 … 左のタグが **`y=`／`r=` の切り替えボタン**（#68）。接頭辞はタグ側が持ち、**入力欄には書かない**
  （`y= r=6` のような二重表示にしない）。押すと軌道 `y=f(x)` ⇄ 結界 `r=f(θ)` が入れ替わり、
  式の変数も `x`⇄`t` へ入れ替える（`swapExprVar`。関数名 `exp`/`max`/`tan`/`sqrt` は巻き込まない）。
  直線 `y=0` から結界へ移るときだけ既定の円 `6` を入れる（半径 0 では張れないため）。
  親切機能として入力欄に `r=` と打っても結界へ切り替わる。
  右に「作図」（作図台の開閉）と「θ 回転 ⟳ 解く」（数値解＋現在角の表示）。
- `z=` 欄 … 変数は盤面の絶対座標 `x`, `y`。右に「属性 自動」（狙い位置での光/闇/中立）。
- **y／r 編集中** … 式から自動検出した係数スライダー（`CoefSliders`・**結界でも出す**・#68）／
  術式チップ（軌道 6 種・結界 5 種をトグルで出し分け）／盤面の通過点フィット（射出のみ）。
- **z 編集中** … `z=f(x,y)` の自由式を入力する。属性・強度は右上の読み出しで常時見えるので、コンソール側には出さない。
- 術式チップの列は**横幅に合わせて折り返す**（横スクロールにしない・#67）。軌道／結界は
  同じ場所に**トグル `[y= 軌道][r= 結界]`** で出し分ける（2列を同時に並べない・#68）。
  トグルは上のタグと同じ切り替えを指す（タグは**現在の状態**を、トグルは**選べる2つ**を見せる）。
- **係数スライダーは端まで動かして手を離すとレンジを取り直す**（つまみが中央へ戻り、そのまま更に大きい／小さい値へ進める・#67）。取り直しは**操作の終わり**（`pointerup`/`keyup`/`blur`）だけで走らせる（値の変化ごとに走らせるとドラッグ中に暴走する）。
- 記号盤（キーパッド）は開閉式。押した記号は**編集中の欄のキャレット位置**へ差し込む。

### 作図台（`DraftPad` / 描画は `render/draftpad.ts`）

関数空間の方眼紙（盤面ではない）。**係数をいじる**／**点から作る**の 2 モード。点は格子点（整数）に吸着する。

- **結界 `r=f(θ)` は極座標の方眼紙**（#69）：同心円＝半径 r の目盛り（4 きざみ・数値つき）、
  放射線＝角度 θ。直交の方眼と目盛りを重ねていたのが「文字が重なる／同心円の意図が分からない」の正体で、
  極座標のときは直交の方眼を描かない。**尺度は固定**（`POLAR_R_RANGE`＝12 が枠の半分）なので、
  `r=6`→`r=9` のように半径だけ変えても輪の大きさが必ず変わる（`rmax` 正規化をやめた・#67）。
  枠より外へ出る結界は読みの行に「12 より外は枠外」と添える。
- **点から作る**は「打った点に**いま書いている式の係数**を合わせる」（#67・[03 §3.3](03-functions.md)）。
  多項式に置き換えるのではなくスライダーが自動で動くので、選んだ術式（sin・指数・1/x…）の形は保たれる。
  **式が変数を使っていないとき**（`y=0` `z=4` `r=6` のような定数式。係数は検出されるが動かしても形にならない）と
  数値リテラルが1つも無いときだけ、従来どおり 1〜3 次の最小二乗多項式（破線プレビュー）へ落ちる（`templateUsesVar`）。
- 反映は必ず**上書き**（元の式に足さない）。多項式へ落ちたときの変数は y なら `x`、z・結界なら `t`。
- 点の吸着は方眼紙ごと：直交は格子点（1 きざみ）、極座標は **θ が `π/8`・r が 1** きざみ。
  極座標で拾った点はそのまま `{u:θ, v:r}` になり、式の変数（`t`＝θ）と一致する。
- y↔r・y↔z を切り替えたら、前の座標の意味で打った点（作図台・盤面の通過点）は捨てる。

## 7.1 解決演出のタイムライン（`BattleCanvas`）

演出は **弾の実速度がそのまま再生速度になる**（演出の速さ＝弾の速さ）。`requestAnimationFrame` で駆動。

### 2 つのフェーズ

| フェーズ | 長さ | 内容 |
|---|---|---|
| **飛行（flight）** | `flightMs` | 弾が飛び切るまで。`MIN_MS(700)`〜`MAX_MS(2300)`。結界がある場合は下限 1600ms。 |
| **余韻（tail）** | `tailMs` | 着弾後の残響。暴発=`MISFIRE_TAIL_MS(1000)`、霧散/結界破壊=`max(IMPACT_TAIL_MS, DISSIPATE_MS+150)`、通常命中/相殺=`IMPACT_TAIL_MS(450)`、なし=0。 |

`flightMs + tailMs` は基本の終了時刻。実際の合計 `realMs` は `animationEndTime` が、
この基本終了時刻・各ダメージポップの絶対終了時刻・各撃破演出の絶対終了時刻の最大値として決める。

### 作成フェーズのオーバーレイ（`BattleCanvas`）

解決演出がない作成フェーズでは、盤面に操作補助を重ねて描く：

- **発射方向の矢印**（`board.drawAimArrow`・#47）：active ally から θ 方向へ**画面 40px 固定**の金の矢印
  （`rgba(244,198,90,.9)`・線幅 2.2・矢じり ±0.5rad×8px）。盤面ドラッグで θ を変えると追従。解決中も出したままにする。
- **射線のローカル軸**（`board.drawRayAxis`）：`y=f(x)` が住む軸。術者から θ 方向へ
  `rgba(244,198,90,.20)` の破線 `[3,5]`、10 ユニットごとに 1×6px の目盛り。長さは `max(48, 1.6×rField)`。
- **プレビュー軌道**（`board.drawPreviewRibbon`）：**アクティブ術者ぶんだけ**を、
  既定では**弧長 `PREVIEW_STUB_ARC = 3.4` までの出だし**だけリボンで見せる
  （`previewFull` を立てると全長）。速いほど太く明るい帯（線幅 `1.4+速度比×3.4`）＋
  4 点おきの法線ヒゲ（z の符号で左右・長さ `min(16, 2+|z|×2.2)`）。
  **どこへ着弾するかは見せない**＝「z(t) は完全情報／当たるかは撃つまで分からない」という設計に対応する。
- **前ターンの軌跡（残像）**（`board.drawTurnTrails`）：直前の解決で飛んだ経路を属性色 α=0.10・線幅 1.2 で薄く残す。
- **通過点の✛**（`drawFitPoints`・#46）：選んだ通過点を連番つきで表示。
- **点ピックのルーペ**（`drawPickLoupe`・#49）：点ピック中のドラッグで、**指の少し上に拡大鏡**（`ctx.drawImage(ctx.canvas, …)` で指の下を `zoom=2.6` 拡大・`imageSmoothingEnabled=false`）を出し、中心クロスヘアと着地点✛を描く。指で点が隠れない。ポインタ移動時は `composeDrawRef` 経由で盤面を再描画してから重ねる。

### 速度→時間の対応（`buildTimeline` / `posAtTime`）

各弾サンプル `{pos, speed, arcLen, z}` を逆速度で積分して時間を作る：

```ts
ds   = arcLen[i] − arcLen[i-1]
v    = (speed[i] + speed[i-1]) / 2                    // physics.flightTimes と同一の定義（#72）
t[i] = t[i-1] + ds / v                                // 失速（v≈0）した先は進めないので時刻を止める
maxTotal = max(全弾タイムライン, エンジンが返す全イベント時刻)
flightMs = min(MAX_MS, max(floorMs, maxTotal × MS_PER_GAMESEC(360)))
msOfGameTime(t) = clamp(0, flightMs, (t / maxTotal) × flightMs)   // ゲーム秒 → 実時間 ms
```

**アニメの時間軸はエンジン（`physics.flightTimes`）と同じ定義**にしてある（#72）。
これで `resolveTurn` が返すイベント時刻（相殺・結界の霧散・暴発）をそのまま実時間へ写せる。
以前は `max(MIN_SPEED=0.5, v)` の床を入れていたため、エンジンが「到達しない」と判定した弾が
画面では最後まで這って到達し、時間軸が本番とズレていた。

`DamagePopup.t` も `timedOnly` で有限値だけを `maxTotal` に含める。ターン全体の実時間は
`animationEndTime` が `flightMs + baseTailMs`、各ポップの「開始 + 950ms + 300ms」、各撃破の
「開始 + 900ms（ボスは 2200ms）」の最大を取る。これにより、飛行窓の終端付近に始まるポップや撃破も
最後まで再生しつつ、非有限の時刻から描画時刻や再生尺を捏造しない。

毎フレーム：`elapsed = now − start`、`e = min(1, elapsed/flightMs)`、`tau = e × maxTotal`（ゲーム内時刻）で各弾位置を線形補間。速い弾は早く着き、遅い弾は長く飛ぶ。

### 演出の発生時刻はエンジンが決める（`render/sceneTiming.ts`・#75）

「演出の**いつ・描くか描かないか**」の判定を1ファイルへ集約している。本編（`BattleCanvas`）とエンドロール（`endroll.ts`）は必ずここを通す。時刻はエンジンが返す**ゲーム秒**（ターン開始=0）で、実時間（ms）への写像はここでは行わない（呼び出し側が `msOfGameTime` で写す）。

| 関数 | 役割 |
|---|---|
| `timedOnly(events)` | `t` が有限でないイベントを除外する（時刻不明のものは描かない） |
| `ringVisible(o)` | 結界を描くか。`bornBroken`（壁・失速で回り出す前に自壊＝一度も存在しない）なら false |
| `ringBreakTime(o)` | 結界の霧散を始めるゲーム秒。`bornBroken` または `breakTime` が `null`/`undefined`/非有限なら `null`（呼び出し側は霧散を始めない） |
| `deathTime(popups, targetId)` | 撃破演出を始めるゲーム秒＝その対象への最後の被ダメージポップの時刻。該当が無ければ `null` |
| `activeDeathIds(starts, elapsedMs)` | 撃破開始時刻が有限で、かつ `elapsedMs` が開始時刻以上になった敵 ID だけを返す。未来に撃破予定の敵は生存スプライトからまだ隠さない |
| `animationEndTime(o)` | ターンの実時間＝`flightMs + baseTailMs`、各ポップの絶対終了時刻（開始 + 表示 950ms + 余白 300ms）、各撃破の絶対終了時刻の最大 |
| `lastEventTime(...groups)` | 全イベントの最終ゲーム秒（再生尺の決定に使う。イベントが無ければ 0） |

**設計原則：時刻が分からないイベントは描かない（0 で捏造しない）。** かつては次の2つのバグがこの原則の欠如から出ていた（#75）：

- **ダメージ数値の一斉表示**：描画側が `trigger`（flash/misfire/heal）を起点に演出開始時刻を再構成していたため、同じ対象に2発以上当たると2発目以降の数値が1発目の時刻に一斉表示された。いまは `DamagePopup.t`（エンジンが返す発生ゲーム秒）をそのまま使う。
- **結界の見かけの早期崩壊**：「回り出す前に自壊した」を `breakTime: 0` で表していたため、「時刻不明を 0 とみなすフォールバック」と衝突し、**何も当たっていない結界が発射直後に崩壊して見える**バグになっていた。いまは「そもそも存在しない（`bornBroken`）」と「破壊された時刻」を型で区別する。

### 種族別の撃破演出（`drawEnemyDeath`・05c §6.5・#46）

敵 HP が 0 になった撃破を、種族ごとに描き分ける（**当たり判定・ダメージ計算には一切影響しない、描画タイムラインのみ**）。`ResolveAnimation.deaths[]`（`{id,pos,species,element,tier,hitboxRadius,boss}`）を App が「このターン hp>0→hp≤0 になった敵」から作り、`BattleCanvas` が `deathStartById[id]` に**その敵への最後の被ダメージポップの時刻**（＝致命打・`sceneTiming.deathTime`・#75）を記録して `progress` を進める。被弾フラッシュ開始（＝最初の被弾）を使うと、2発当てて倒したときに1発目のタイミングで消滅が始まってしまう。該当ポップが無い（掃射など数値を出さない撃破）ときだけ、飛行終盤（`e≥0.9`）を保険に開始する。`hideEnemyIds` は `activeDeathIds` を使い、**経過時間がその敵の撃破開始時刻に達した後だけ**生存スプライトを隠して消滅アニメへ譲る。未来の撃破時刻が登録済みでも、命中前の敵は隠さない。

- **DoT（burn）撃破の消滅演出（バグ修正）**：継続ダメージ（闇属性が付与する `burn`）は解決フェーズ（`resolveAllyCasts`）ではなく**ターン開始の `prepareTurn`** で適用される（`turn.ts` には DoT 参照がない）。そのため通常命中・掃射・暴発と違い、解決直後の before/after 比較（`battle.enemies`→`after.enemies`）では DoT 撃破が拾えず、以前は**種族別の消滅アニメが一切再生されずに敵が無演出で消えていた**。現在は `onAnimationDone` で `prepareTurn(after)` を実行した直後に「`after` で hp>0→`prep.state` で hp≤0」になった敵を検出し（撃破前スナップショットは `after.enemies` から取る）、`deaths` だけの短いアニメを一度挟んでから次ターン盤面へ進む。この間は `pendingPrepRef` に準備済み状態を退避し、`onAnimationDone` が `prepareTurn` を**再実行しない**（DoT の二重適用を防ぐ）。ロジック（hp・勝敗）は不変で演出のみ追加。
  - **同ターンに主解決の撃破と DoT 撃破が同居するときの盤面（バグ修正）**：burn 中間アニメを流す前に**盤面を `after`（主解決後の敵配列）へ更新**してから `setAnimation({deaths:burnDeaths, bossView})` する。これをしないと、`BattleCanvas` が主解決前の `battle.enemies`（全員 hp>0）を描き、`hideEnemyIds` は burnDeaths の ID しか含まないため、**主解決で撃破済みの敵が生存スプライトで一瞬“生き返って”見えた**。`after` を渡せば `drawEnemies` が hp≤0 の主解決撃破敵をそもそも描かず、burnDeaths の敵だけが消滅アニメで消える。ボスを burn で倒す場合の外見崩れも防ぐため `bossView`（phase/finale/outcome）も `after`/`prep` 準拠で渡す。

| 種族 | 消滅の見た目 |
|---|---|
| 原型（proto） | ひび割れて光の粒になって崩れる（基準形） |
| 鋼鬼（oni） | 膝から沈み、鎧の破片が飛散→一部は地面に瓦礫として残ってから消える（実体・重量感） |
| 亡霊魔術師（wraith） | ローブがほどけ、上方へ属性色の光の筋（3〜4本）となって静かに消える（破片なし） |

### 暴発の演出（`drawMisfire`＋ステージ全体演出・#29/#41）

**紫（闇）と黄（光）の腕がぐるぐる回りながら中心へ集まる大渦**（虚式・茈のイメージ）。**加算合成（`globalCompositeOperation='lighter'`）**で、紫と黄は**完全には混ざらず色を残し、重なった所だけ白っぽく光る**。中心は白熱し、進むほど白核が育って**最後は中心が白く埋まる**。**効果範囲（AoE）の内側を渦で埋め尽くす**（実効半径 `effR = aoeRadius × scale × 1.18` で少しだけ外へはみ出す）。**AoE 境界には白い明滅破線円**を `aoeRadius` ちょうどに描き、実ダメージ範囲を明示。

- **渦の腕**：`ARMS=12` 本（紫/黄が交互）×`PTS=32` 粒のらせん。各粒は `t = frac(k/PTS − inflow)` で**縁→中心へ流れ続ける**（常に AoE を充填）。角度は `base + t·WIND·2π + spin`（半径で巻く＝らせん）。`spin = progress×10`（ぐるぐる回る）。紫は黄より暗く見えるので濃いめ（α×1.45）に出して色を残す。
- **土台ハロ**：紫・黄の薄い放射グラデを少しずらして重ね、隙間なく埋める。
- **きらめき火花**：紫/黄/白が明滅しながら渦に散る（58 個）。
- **中心コア＋十字の星スパーク**：白熱コアは `progress²` で巨大化（最後は白飛び）。中心から白い十字スパークが明滅して伸びる。

**ステージ全体演出（`BattleCanvas`・#41）**：暴発中はフレーム全体を `ctx.translate` で**ガタガタ揺らす**（強さは爆発直後が最強→減衰、振幅 ~9px。ズレの隙間を防ぐため先に背景で塗る）。さらに上空から**遺跡の破片**（`drawFallingDebris`：石片がフィールド円内に降ってくる）が落下する。

### 画面揺れ（`shakeOffset`）

```ts
shakePhase = elapsed × 0.05
x = sin(shakePhase×1.3 + idSeed) × intensity × 5
y = cos(shakePhase×1.7 + idSeed×1.5) × intensity × 5
intensity = 1 − (elapsed − flashStart)/FLASH_MS    // 1→0 に減衰
```

`idSeed(id)` は ID から決定的に作る（揺れの位相を個体ごとに変える）。

### ドットの衝撃波（`drawPixelBurst`・#77）

相殺の衝撃波は `drawPixelBurst`、属性別の着弾は `spellfx.drawSpellImpact` が担当し、共通の `pixelShockwave` を使う。滑らかに広がる輪ではなく
**段で広がる**（進行を離散化し、半径をドット格子へ丸める）：

```ts
steps = 2 + round(powerFrac×4)              // 何段で広がるか＝威力
q     = floor(progress × steps) / steps     // 「今どの段か」を切り替える（補間しない）
半径   = round((r0 + q×span) / unit) × unit  // **絶対ピクセル式のまま**格子へ丸めるだけ
n     = max(8, round(2πr / (unit×2)))       // 粒の数は円周に比例（1つおきに白熱と属性色）
```

> **半径を「段 × ドット幅」から組み立て直してはいけない。** ドット幅は縮尺の小さい盤面で下限 2px に
> 張りつくので、`半径 = 段 × unit × 1.6` にすると相殺の輪が **141px → 16px** へ潰れ、
> 「必ず目に入る」演出が消える。ドット絵にするのは**進み方と粒**であって、演出の大きさではない。
> 回帰テストは `render/pixelfx.test.ts`（`unit=2` でも到達半径が 120px を超える）。

- **着弾**（`drawImpactShockwave`→`drawSpellImpact`・420ms）＝命中点の属性と威力を受け取り、属性色の二重衝撃波・白熱の芯・破片を描く。光は放射状の光条、闇は回転する欠片、中立は控えめな粒。`SPELL_VFX.impact` は9段、輪の目標半径36〜55px、内側の輪は進行0.18遅れ、光闇の破片12個、白熱芯は進行0.4まで。半径は演出用で、ダメージ範囲ではない。
- **発射陣**（`drawLaunchFlash`→`drawCastSigil`・260ms）＝8段の収束→解放。二重の輪に8区画×4ドットとルーン状の刻みを置き、光は十字、闇は逆回転する輪、中立は小さな核を添える。`SPELL_VFX.cast` の収束開始半径26px、内側比0.65、解放開始の進行0.375を使う。
- **尾の火花**（`drawSpeedSparks`→`drawSpellWake`）＝現在位置より前の実サンプルを2点刻みで最大7個参照する。威力比0.12以下では出さず、位相は1/8刻みで進める。光は後方への短い光条、闇は左右交互の渦片、中立は淡い粒。未到達の経路を外挿せず、粒を次フレームへ蓄積しない。

これらの定数は `src/data/spellVfx.ts`、実体は `src/render/spellfx.ts`。発射陣・着弾の既存時間枠は延長しない。
時刻・位相と解決済みサンプルだけで再計算し、見返しで同じ時刻に同じ描画へ戻る。各描画関数はCanvas状態を保存・復元する。

`BattleCanvas` は `anim.bullets` の各命中を `msAtArc(i, im.arcLen)` の時刻で個別に描く。
最初の一発の `flashStartByTarget` にまとめず、各命中サンプルの `z` と `powerSizeFrac(speed, z)` を渡すため、
同じ対象への連続命中でも各衝撃が残る。発射陣の属性は先頭サンプル `pts[0].z` に固定する。
- **相殺**（`drawParryFlash`）＝光・闇を 16ms ずらして 2 重に重ね（`r0=9+pw×22, span=44+pw×66`）、中心に段で欠ける白熱の円盤
  （`pixelDisc`・階数 `round((2+pw×3)×(1−progress))`）＋16 方位へスナップした 12〜22 本の破片
  （1 ドットずつ並べた線・長さ `(20+pw×52)×progress^0.55`）。`pw = min(1, power/140)`。

**相殺（パリィ）の演出**（`drawParryBurst`・`PARRY_MS = 900`ms）＝`drawParryFlash` ＋ 進行 62% まで
上へ抜ける「相殺」の文字。従来の青白い火花 `drawClashSpark`（`CLASH_MS=460`）も重ねる。
**火花の実体は `drawParryFlash` 1 か所**で、エンドロールは文字なしでこれを呼ぶ
（かつてエンドロールが同じ絵を独自に書き直していて、片方だけドット絵から取り残された）。

### 魔法演出のドット絵文法（`render/pixelfx.ts`・#77）

魔法の演出は**すべて整数座標の矩形（ドット）だけ**で描く。放射グラデーション（`createRadialGradient`）・
`shadowBlur`・`lighter` 合成・なめらかなフェードは使わない（DESIGN.md §4.5／§6）。
語彙は `render/pixelfx.ts` の 1 か所に集約し、戦闘アニメ（`board.ts`/`draw.ts`）とエンドロール
（`endroll.ts`）が同じものを呼ぶ。

| 関数 | 役割 |
|---|---|
| `dotPx(vp)` | ドットの粒度＝`max(2, round(scaleOf(vp)×0.16))`。**術者スプライトの 1 ドット幅と同じ**＝魔法とキャラが同じ格子に載る |
| `bulletDotTier(speed, z, vp)` | 弾を半径何ドットで描くか＝`round(bulletRadius(speed,z)×scaleOf(vp) / dotPx(vp))` |
| `dot` / `pixelDisc` / `pixelRing` | ドット 1 個／ドットの円盤（行ごとに 1 矩形へまとめる）／ドットの輪 |
| `quantAlpha(a, steps=4)` | 濃さを段に落とす。連続フェードは粒が霞んでグローに戻るので禁止 |
| `snapAngle(rad, dirs=16)` | 回転する棘・破片を 16 方位へスナップ＝カクついた回転にする |
| `walkPath(pts, upto, toPx, step, cb)` | 画面座標のポリラインを**弧長で**等間隔に歩く。サンプル間隔は速度でばらつくので、これを通さないとドットの密度が速度で変わる |

**階数は威力から作らず、必ず当たり半径から引く**（#72）。`tier = 1 + round(powerFrac×3)` のように
威力から独立に段を作ると、`tier_max × dotPx ≒ 0.64×scale` が最小の当たり半径 `0.85×scale` を
下回り、**最大威力の弾ですら最弱の当たり判定より小さく描かれる**。回帰テストは `render/pixelfx.test.ts`
（描かれる半径と当たり半径の差が 1/2 ドット以内）。

**ドット化する範囲**＝飛翔中の魔法・結界・接触の演出（弾／軌跡／煙／火花／結界の帯と粒／
衝撃波／相殺／霧散）。次の 3 つは**意図的に従来のまま**にしてある：

| 残すもの | 理由 |
|---|---|
| **暴発** `drawMisfire` | 加算合成の大渦（紫と黄の腕・中心は白熱）は**仕様が指定した絵**（graph_mage-spec.md §3.10・#41）。ドット化は仕様変更になるので触らない |
| **プレビュー軌道** `drawPreviewRibbon`・**前ターンの残像** `drawTurnTrails` | 作成フェーズの「下読み」。細い滑らかな線のままにして、**いま飛んでいる魔法（ドット）と一目で区別**できるようにする |
| **壁のえぐりバースト** `drawCarveBurst` | もともと四角ドット。粒はやや大きめ（`scaleOf×0.34`）＝石片は魔法より粗い、という区別を残す |

### 弾の色・大きさ（`drawBullet`・#72/#77）

```ts
bulletColorOf(z):  光→#f4c430 / 闇→#8a6fd6 / 中立→#d9d4ea
sFrac  = min(1, strengthOf(z) / FIELD.sMax)         // 0..1（属性強度）
unit   = dotPx(vp)                                  // ドットの粒度（術者スプライトと同じ）
tier   = bulletDotTier(speed, z, vp)                // **当たり判定の半径そのもの**（#72）
```

芯・本体・結晶・渦片・輪のドット中心は `tier×unit`（当たり半径をドットへ丸めた値）の内側に置く。矩形の四隅はドット丸め誤差を許容する：

- **光**＝金色の本体・白い芯・回転する十字結晶。外縁の4つの刻みは逆方向へ回転する。芯の階数は `floor(tier×0.25)`。
- **闇**＝暗紫の本体に半周ずらした2本の紫の渦片。各5ドットを内側から外側へ巻き上げ、中央に `floor(tier×0.3)` の暗い核を置く。
- **中立**＝小さな銀白の芯と控えめな明滅。芯の階数は `floor(tier×0.3)`。
- **外縁の輪**＝全属性共通で半径 `tier×unit`、16点。濃さは `quantAlpha(0.3+sFrac×0.4)`。回転は `snapAngle` で16方位へ量子化し、位相は内部形状と明暗だけを変える。速度0でも核と輪は消さない。

**外縁＝当たり判定の半径**（`game/collision.bulletRadius`＝`0.85〜1.5` ユニット・#72）。外側の装飾輪は増やさず、属性は内部形状、強度は輪の明るさで読ませる。回帰テストは `render/pixelfx.test.ts` で全属性・速度0・複数位相の四隅の境界と、位相往復時の同一描画を確認する。
見えている大きさがそのままぶつかる大きさになるので、「当たったように見えたのに素通りした」が起きない。
大きさ（`tier`）は**威力（=その点の速度×属性強度）に比例**する（#45）。

### 魔法の3つの読み（#74）

**一目で属性強度・威力・速度が分かる**よう、チャンネルを1つずつ別の見た目へ割り当てている：

| 読みたい値 | 見た目 | 実装 |
|---|---|---|
| **属性強度 \|z\|** | **軌跡のドットの大きさ**（`TRAIL_W_MIN=0.12` 〜 `TRAIL_W_MAX` ユニット・ドット格子の整数倍へ丸める） | `board.trailWidthPx(z, vp)` |
| **威力（速度×強度）** | **弾本体の大きさ**（＝当たり判定 `bulletRadius`）＋軌跡の**白熱**＋**ドット絵の煙**の量 | `draw.drawBullet` / `board.drawFlightPath` ②/ `board.drawPowerSmoke` |
| **速度** | **魔法が動く速さそのもの**（`buildTimeline` が `physics.flightTimes` と同一定義） | `BattleCanvas.posAtTime` |

- **色相は常に属性**（金＝光／紫＝闇）。威力は色相を動かさず**明るさ（白熱）**だけで語る＝属性の読みを壊さない。
- `TRAIL_W_MAX = COMBAT.bulletRadiusMin × 1.2`（≒1.0 ユニット）。**弾本体の最小直径 `2×bulletRadiusMin`（=1.7）より必ず細い**ので、強度が最大・速度が最小の魔法でも「太い軌跡を当たり判定と読み違える」ことがない。当たり半径を調整しても自動で追従する。
- **太さの規則は `board.trailWidthPx` 1か所だけ**。戦闘アニメとエンドロールが同じ関数を呼ぶので、片方だけ見た目が変わることがない。値は**ドット格子（`dotPx`）の整数倍へ丸める**（#77）：格子に乗らない太さは弾・スプライトと粒度がズレて「にじんだ帯」に見える。丸め幅は 1 ドット（±`unit/2`）で、`TRAIL_W_MAX` に足しても弾の最小直径を超えないので上の規則は保たれる（`render/pixelfx.test.ts` が固定）。

#### 軌跡ドットの濃さ（`trailDotAlpha`・#74）

軌道サンプリングの弦長細分割により軌跡の解像度が向上した一方、**軌跡ドットの濃さを属性で少しだけ変え**、光と闇の「現れ方」の差を可視化している（#74）。規則は `trailDotAlpha(z, head)` 1か所に集約し、戦闘アニメ（`board.drawFlightPath`）とエンドロール（`endroll.ts`）で必ず同じ見た目になるよう統制する。ドット絵の作法（なめらかにフェードさせず段で表現する）は光闇とも維持。

| 属性 | head の段分け | 各段の濃さ α | 特徴 |
|---|---|---|---|
| **光** | `head > 0.55` / `head > 0.33` / その他 | 0.85 / 0.5 / 0.25 | パッと点く。頭側が早く全点灯に達する |
| **闇** | `head > 0.92` / `head > 0.62` / `head > 0.3` / その他 | 0.45 / 0.7 / 0.5 / 0.35 | 遅れて滲み出て尾が長く残る。頭の直近だけ一段暗く、尾の減衰が緩やか |
| **中立** | `head > 0.66` / `head > 0.33` / その他 | 0.75 / 0.5 / 0.25 | 従来どおりの 3 段 |

エンドロール側は `trailDotAlpha(src.z, head) × fade` として終端のフェードアウト（`fade`）を掛け合わせている。

### ダメージ／回復の数値（`drawDamageNumber`・#42/#75）

被弾・回復のたびに、対象の頭上に数値が**浮かび上がって（上へ昇りながらフェード）**表示される。`resolveTurn` が `DamagePopup[]`（位置・量・種別・対象ID・トリガー・**発生ゲーム秒 `t`**・#75）を集め、`BattleCanvas` が描く。

- **色**：属性色（光=金 `#f4c430`／闇=紫 `#b483ff`／中立=淡）。**暴発=白 `#ffffff`**、**回復=緑 `#5ad16a`（先頭に `+`）**。
- **大きさ**：受けたダメージ量に依存（`size = round(15 + min(15, amount/11))`px）。大ダメージほど大きい。
- **タイミング**：`timedOnly` が `p.t` の有限なポップだけを描画対象に残し、開始時刻は**エンジンが返す発生ゲーム秒 `p.t` をそのまま実時間へ写す**（`msOfGameTime(p.t)`・#75）。命中＝`timeToArc(flight.samples, hit.arcLen)`、掃射＝リング上の到達時刻（`orbit.orbitSweep` が返す `OrbitHit.t`）、暴発＝爆発時刻（`blastOrbits` と同一変数）、回復＝固定 `0`。`trigger`（flash/misfire/heal）は色・被弾フラッシュ本体との対応づけに使うだけで、ポップの発火時刻には使わない。非有限の時刻は境界で除外し、0 や飛行終端へ丸めて表示しない。
  - **背景（#75）**：以前は `trigger` を起点に描画側が時刻を再構成していたため、同じ対象に2発以上当たると**2発目以降のダメージ数値が1発目の時刻に一斉表示**されていた。**演出の発生時刻はエンジンだけが決める**（`render/sceneTiming.ts` の設計原則）。
- **重なり回避**：数値どうしが矩形で衝突する間は上へずらして積む（最大 28 回）。画面上端へはみ出さないようクランプする。
- **表示時間**：`POPUP_MS = 950`ms。ターンの総尺は各ポップについて `開始時刻 + POPUP_MS + 300ms` という絶対終了時刻を候補に含める（飛行時間を二重加算しない）。
- **描き方**（`board.drawDamageNumber`）：黒の輪郭（線幅 `max(3, size×0.26)`・`miterLimit=2`）→ 2px オフセットの黒影 → 本体色。回復は先頭に小さい「＋」。**画面揺れの外**に描くので暴発中でも読みやすい。

### 障害物のテクスチャ（種別ごと・#56）

壁の質感は**ピクセルアートのタイル画像**を素材内（`source-atop`）に `createPattern(tile,'repeat')` で敷き詰める（`src/render/textures.ts` の `getWallTexture(kind, element)`。小タイルを生成してキャッシュ。`imageSmoothingEnabled=false`、下地の属性色を活かすため `globalAlpha≈0.62` で重ねる）。画像が取得できない環境では下の手続き描画にフォールバック。将来は `getWallTexture` を `new Image()` の実 PNG 読み込みに差し替え可能。

| 種別 | 下地色 | タイル（ピクセルアート） |
|---|---|---|
| normal/属性 | light=茶 `rgba(120,98,46,.94)` / dark=紫 `rgba(62,52,104,.94)` / 中立=灰 | 石積みレンガ（属性で色味・段ごとに半個ずらし） |

| tough | 濃灰 `rgba(56,56,70,.96)` | レンガ＋鋲（各レンガ中央の点） |

## 7.5 見返し（プレイバック・`PlaybackBar`・#DC移植）

解決済みのターンを選び、経路・命中・結界の削れを**スクラブしながら**見返せる。ゲーム進行には影響しない。

- 見返せるのは**直近 1 ターン**だけ（`REPLAY_KEEP`・#69）。アニメーションを**解決前の盤面ごと**保持する
  （[09 §9.6](09-data-model.md)）。選択肢が1つなのでターン選択ボタンは出さない。
- `BattleCanvas` に `playback: {paused, seekMs, seekToken, rate}` と `replay` を渡すと、
  内部の時計を外から止める／飛ばす／速さ（×1・×0.5・×0.25）を変えられる。
- 見返し中は終端で `onAnimationDone` を呼ばない（その位置に留まる）。
- **演出の開始時刻は「経過時刻から引ける値」にする（#70/#75）**：被弾フラッシュ・衝撃波・
  壁を削った赤い破片・パリィの火花・結界の霧散は、**その演出が始まるゲーム時刻**を先に求めてから
  `(経過時刻 − 開始時刻) / 持続` で進行度を出す。弾の到達時刻は飛行サンプルの弧長から引き
  （`render/effectTiming.ts` の `gameTimeAtArcLen`）、パリィ・霧散はエンジンが返す衝突時刻を使う。
  **ダメージ表示・撃破はエンジンが返す発生時刻をそのまま使う**（`DamagePopup.t`／`sceneTiming.deathTime`・#75）ので、弧長からの逆算は経由しない。
  - 旧実装は「到達したフレームの現在時刻をラッチする」方式で、順再生でしか正しくならなかった。
    シークで一斉発火するのを避けるため `preExpire` で過去の演出を握りつぶしていたので、
    **その時刻に進行中だったはずの演出が何も出ない**（見返しで止めるとエフェクトが消える）状態だった。
  - いまはラッチが「発生時刻そのもの」なので、握りつぶしが要らない。
    まだ来ていない演出は進行度が負になって自然に描かれない。
  - 実測：シーク位置を 17 点掃引して修正前後を比べると、飛行中の全位置で演出が増えた
    （最大 7,546px／飛行が終わった位置は差分 0px＝もともと出ていた）。
- **絵はすべて経過時刻の関数にする（#69）**：壁の穴の開き具合は弾の弧長から毎フレーム組み直し、
  被弾・火花・霧散・破片・撃破はシークでラッチを捨てる。**結界リングの流れる粒**だけは
  `board.ts` 側がフレーム数で進む持ち越し状態だったので、`render/ringPhase.ts` の
  `seedRingPhases` で経過時刻から位相を組み立てて描画直前に上書きする。
  これで同じ再生位置なら**どんな順に行き来しても同じ絵**になる（実測：往復しても差分 0px）。
  再生速度（×0.5／×0.25）でも粒の流れがちゃんと遅くなる。

## 7.6 手引きの図版（`render/tutorialFigures.ts`・`Guide`）

8 枚の canvas 図で「y が道／θ で回す／z が属性／強い属性は重い／盤面の輪が z(t)／
当たるかは撃つまで分からない／結界とパリィ／壁と暴発」を**動かして**見せる。

## 7.7 エンドロール（`render/endroll.ts`・`Endroll`）

エンディングの後に流れるクレジット背景。**本物の敵AI同士（LIGHT MAGE ⇄ DARK MAGE）が延々と撃ち合う**。

- **計算は本番と完全に同一（#72）**：計画は `planEnemyShots`、解決は **`resolveTurn` をそのまま1回呼ぶ**。
  相殺・結界の迎撃・障害物の削り・暴発・ダメージ・状態異常はすべて本番の実装が返した結果を描くだけで、
  この層はロジックを持たない。演出の時刻もエンジンが返すゲーム秒（`flightTimes`／`clashes[].t`／`breakTime`）を使う。
  「いつ・描くか描かないか」の判定（結界を描くか・霧散をいつ始めるか）も本編と同じ `render/sceneTiming.ts` を通す（#75）。
- **盤面の縮尺も本編と揃える（#75）**：ビューポートは `unitsRadius = FIELD.rField`、`pan = {x:0, y:-UR/3}`。
  以前は `unitsRadius = FIELD.rField × 0.8`・`pan.y` 固定 `-8` で、本編より 1.25 倍ズームしていたため
  同じユニット半径の魔法が画面上で大きく見えていた。エンドロールの盤面生成は常に `FIELD.rField` の
  広さを前提にしている（`makeObstacles`・`planOne` が渡す `fieldR` も同じ）ので、カメラもそれに合わせる。
- 1 幕＝両者が同時に撃つ（A 側＝味方の発射、B 側＝敵弾として `resolveTurn` に渡す）。
  干渉は本番と同じく**ゲーム時刻の早い順**に解ける。
  かつては迎撃順・ダメージ式・相殺距離をこの層で書き直しており、**結界が壁を無視して張り続ける**
  （`orbitWallBreak` を呼んでいなかった）・**相殺より先に迎撃を解くので消えたはずの弾が結界を壊す**
  といった本番との食い違いが出ていた。
- やられた側だけ **LVL +1・全回復**、壁は別配置に組み直す。**LVL 7（同時 4 発）で決着したら両者 LVL 1 へ**。
- **画面の LVL 表記＝本編の敵 LVL そのもの（1〜7・#76）**。`Enemy.level` にこの値をそのまま入れるので、
  式の複雑さ・係数の可動域（`ENEMY_FIT_COMPLEXITY`）も結界の複雑さ（`ENEMY_GUARD_PLANNING` の段階表）も
  本編と同じ段階で解禁される＝**エンドロールを見ていれば最上位（LVL7）の敵の振る舞いまで一通り見られる**。
  得意関数の解禁順も本編に合わせてあり、多重サイン（`harmonic`）は LVL6 以降だけが持つ（05b §2）。
- **LVL が上がるほど壁は硬く、経路は複雑になる（#76）**：耐久は `fragile→normal→tough` と硬い側へ寄り
  （`kindPool`。**LVL7 は `tough` だけ**）、壁の本数は `min(18, 2+LVL*2)` 本（`obstacleCount`＝LVL7 で名目16本・
  実配置は間隔の制約で平均10本前後）まで増え、**視線を塞ぐ壁が 1→2→3→4 本**に増える（`blockerCount`）。
  2本以上は A→B の直線上で**左右交互**にずらすので、抜け道が左・右・左…と入れ替わり、
  一度曲がって戻るだけの軌道では抜けられない＝高 LVL ほど高次・多重の折れが要る経路になる。
  壁の半径も LVL とともに太くなる（`blockerRadius`／`scatterRadius`）。**1撃の削りは
  `carveMaxRadius(2)×tough(0.32)=0.64` が上限なので、太さがそのまま耐久になる**のが最大の効き所。
  **LVL7 の視線を塞ぐ壁は A→B 方向に円を3つ重ねた「厚い衝立」**（`SLAB_MIN_LEVEL`）＝迂回路の形は
  変えずに掘り抜くのに要る発数だけを増やす。
- **術者の周囲だけは障害物を少なめにする**（`MAGE_CLEAR`：視線を塞ぐ壁は素材の縁まで 4.6、散らす壁は 7.4）。
  撃ち出しと着弾の周りが壁で埋まって「出た瞬間に自爆・何も起きない」絵になるのを防ぐ。
- **暴発型（`ruptor`）は最上位でも1発まで（`MAX_RUPTORS`）**。暴発のダメージは**固定 180**
  （`sMax(5) × maxFlightSpeed(24) × opposite(1.5)`・[04 §3.5](04-magic.md)）で HP140 を一撃で消し飛ばし、
  しかも AoE は**距離だけで判定する**（`resolveMisfire`）ので**壁では遮れない**。かつて LVL7 の配分は
  `[結界, 暴発, 火力, 暴発]` と暴発2発だったため、壁をどれだけ厚くしても両陣営が初手で相打ちになり、
  **LVL7 の幕が1ターンで終わっていた**。1発に減らして `[結界, 暴発, 火力, 迂回]` にした
  （実測・LVL7 の1幕あたり：どちらかKO 73%→32%／**相打ち 48%→2%**／爆発 1.60→0.32 回。
  一方で「何か当たった幕」は 58〜62% を保つので、盤面が無風になることはない）。
  結界の極性も LVL6 以降は指定せず、**読み（#76）に飛来弾の反対極を選ばせる**（LVL5 までは従来どおり幕ごとの交互張り）。
  **`unbreakable` は使わない**：エンドロールは決着でしか LVL が進まないため、削れない壁で道が塞がると
  同じ幕を延々と繰り返して進行が止まる。硬い壁でも削りは幕をまたいで持ち越されるので、いずれ必ず道が開く
  （回帰テストは `render/endrollLevels.test.ts`：どの LVL でも直進は塞がれ、かつ迂回路は必ず残る）。
- 敵AIの計画は重いので、**幕の尻尾で 1 フレーム 1 手ずつ**先取りして次の幕を組む（切り替わりで描画が止まらない）。
  **決着（KO）した幕でも先取りする（#76）**：KO の瞬間に「次の幕の盤面」（LVL 更新・全回復・組み直した壁）を
  `Bout.next` として確定させ、先取りと幕の終わりの状態更新が同じものを使う（壁の乱数を引き直さないので、
  計画した盤面と実際に撃つ盤面がズレない）。以前はここで先取りを捨てていたため、**LVL が上がる次の幕だけ
  計画が全部同期で走り、ちょうど LVL 更新のタイミングで画面が止まっていた**（実測 944ms → 約500ms）。
  なお **B 側の計画は `resolveTurn` の内側**なので先取りできず、幕の切り替わりに残る負荷はこれ（高 LVL で数百 ms）。
- **描き方も本編と共有する**：弾の太さは `board.trailWidthPx`、結界の帯と粒は **`board.drawOrbitRing`**（`quiet=true` で
  読み値だけ伏せる）。粒は**その場のリング速度**で流れるので、`|z|<zRef` の区間で加速し `|z|>zRef` の区間で詰まる。
  かつてはこの層が「3.4 秒で必ず一周・向きは陣営で反転」という自前の回転を描いていて、
  **加速する結界が一定速度に見える／闇側だけ逆回りに見える**という食い違いが出ていた。
- **結界の効果も本編と同じ実装で描く**：`ringAverageAttr` で属性を決め、光＝`drawLightAura`（癒やしの場）、
  闇＝`drawDarkVeil`（視認阻害）を `quiet=true` で呼ぶ。効果を出すのは霧散していない結界だけ
  （エンジンの判定・turn.ts §5.5 と同じ条件）。
- **A 側と B 側の AI には差をつけない。** B 側は `resolveTurn` の中で
  「見えている相手の結界・自前の結界（#71）・前の幕の読み（#75）・最新の盤面」を受け取るので、
  A 側の `planOne` にも同じものを渡す：
  - 自前の持続結界（`owner==='player'`）
  - 一つ前の幕で B が撃った手（`Bout.after.enemyCasts` → `predictAllyShots`）
  - **盤面は `Bout.after`**（この幕を解決し終えた状態＝次の幕の開始時点）。先取り計画は幕の尻尾で走るので、
    ここを現在値のままにすると A 側だけ「削れる前の壁・古い結界・古い HP」で計画してしまう。
  - 決着（KO）したら両陣営の「前の手の読み」を捨てる（仕切り直し）。
  - 状態異常（`statuses`）と隠蔽（`concealed`）は**両陣営とも渡さない**。隠蔽はエンジン上
    味方側にしか付かないため、渡すと A 側だけが「隠れられる」非対称になる。

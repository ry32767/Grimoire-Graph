# 05. 敵・敵 AI

敵の定義は `src/data/stages.ts`（`enemy()` ファクトリ）、AI は `src/game/enemyAI.ts`（軌道計画の中核は `src/game/enemyPlanning/` に分離。§5.4）。

> 攻撃パターン4種（火力型/迂回型/暴発型/守護型）と、パターンごとに使える軌道関数・z場関数の組み合わせは [05b-enemy-archetypes.md](05b-enemy-archetypes.md) にまとめている。本ファイルは `role`/`family` の基礎仕様、05b はその上に乗るパターン設計。**具体的な敵の名前・数値・強化ティアは [05c-bestiary.md](05c-bestiary.md)（図鑑）を参照。**

## 5.1 敵の構造（`Enemy` 型）

| フィールド | 意味 |
|---|---|
| `name` / `pos` / `hp` / `maxHp` | 名前・配置（=発射元）・HP |
| `element` | 被ダメージ相性に使う**防御属性**（light/dark/neutral） |
| `hitboxRadius` | 被弾ヒットボックス半径（既定 `enemyHitbox=1.8`、ボスは 3.6） |
| `family` | 得意関数の**系統**（見た目で判別・AI が最適化する関数族） |
| `families?` | 追加系統（#28：1〜2 個）。AI は family＋これらを全部試して最良を選ぶ |
| `role?` | 戦い方（attacker / breaker / guardian）。未指定は attacker |
| `castInitialSpeed` | 敵弾の初速 |
| `castZ` | 敵弾の代表 z（符号=属性の基準）。`castMag`（既定 3）×極性 |
| `castZField?` | 敵弾の z 場（未指定なら定数 castZ の場） |

`enemy()` ファクトリは `castZ = element==='light' ? +castMag : element==='dark' ? −castMag : 0` を設定。
ただし AI は攻撃時、**属性に関係なく対象の弱点（反対極）を自由に突く**（§5.4）ので、`element` は主に被弾相性と見た目に効く。

## 5.2 系統（family・#17）

弾の形で判別できる「得意関数」。頭上の記号（glyph）とゴースト軌道で予告される。

| family | ラベル | AI が組む軌道（`buildEnemyTrajectory`） | 形状係数候補 |
|---|---|---|---|
| `line` | 直進 | `g(x)=0`（直線） | `[0]` |
| `arc` | 弧 | `g(x)=shape·x²`（緩い放物） | `[-0.09, -0.04, 0.04, 0.09]` |
| `wave` | 波 | `g(x)=shape·sin(0.45x)` | `[1.5, 3]` |
| `spiral` | 渦 | `f(t)=shape·(t+angle)`（極座標・渦巻き） | `[0.7, 1.1]` |
| `abs`（#46） | 折れ | `g(x)=shape·\|x−h\|`（絶対値・V字） | 05b-enemy-archetypes.md §2 参照 |
| `exp`（#43） | 昇り | `g(x)=shape·(e^(kx)−1)`（指数） | 05b-enemy-archetypes.md §2 参照 |
| `poly34`（#43・#46で3〜5次に拡張） | 捻れ | `g(x)=shape·(x³−c·x)` 等（3〜5次） | 05b-enemy-archetypes.md §2 参照 |

`ARCHETYPES` がラベルと glyph を保持。狙い角オフセットは spiral 以外で `[-0.28,-0.14,0,0.14,0.28]`、spiral は `[0]`。

> `exp`／`poly34` は攻撃パターン別の関数運用（05b-enemy-archetypes.md）向けに追加された family。使用可否・組み合わせはパターンごとに定義される（同ドキュメント §2）。

> `ruptor` は既存の `family` をそのまま使う（多くは `line`。緩い弧も可）。見分けは family の glyph ではなく、**専用の警告アイコン（ひび割れた記号）**と、破綻点に出る赤いマーカーで行う（§5.4b）。

## 5.3 ロール（role・#28）

| role | パターン名（05b） | 説明 |
|---|---|---|
| `attacker`（既定） | 迂回型 | 味方へ最大ダメージを狙う。壁は避けて通る（幾何経路探索＋family フィット・§5.4）。 |
| `breaker` | 火力型 | 壁を貫いてでも味方へ届かせる。**障害物ペナルティを受けない**（壁よけ軌道も使わず直進で貫く）。 |
| `guardian` | 守護型 | 攻撃せず、自陣（**自分＋近くの味方**）を守る**防御用周回結界**を張る。外形は「素材に触れない上限（自由半径）」と「味方を覆う下限」を満たす `r=f(θ)` を**フーリエ級数へ制約付きフィット**して決める（#71・05b §5.4）。z は自陣属性（交互張り個体は `guardZSign`）×`zRef` を基本に、脅威方向の迎撃威力が最大になる場を本番物理で選ぶ（方向づけ個体＝`directedAura`・#47）。**既に張ってある結界と同形状は避けて別の輪を重ねる（上限2枚）**。光の結界は囲んだ敵陣を毎ターン `orbitHealAmount(=30)` 回復する。 |
| `ruptor`（崩し手・#42） | 暴発型 | 味方（または壁）を狙い、**z 場に極を仕込んで対象近傍で暴発**を起こす（04-magic §4.3 の暴発と同一）。威力は暴発仕様どおり常に最大・光闇両属性。**詳細は §5.4b**。 |

guardian の結界も「反対極のみ相殺・同極は透過・壁/失速で霧散」という味方の結界と同じルール（[04-magic.md](04-magic.md) §4.6）。**ruptor の弾も例外ではなく、この同じルールに従う**（§5.4b）。

## 5.4 敵 AI の攻撃計画（`planEnemyShot`・`src/game/enemyPlanning/`）

候補軌道は **3層構成**で作り、最後に本番物理で必ず再検証してから辞書式ランクで最良を選ぶ：

1. **幾何経路探索**（`enemyPlanning/routeSearch.ts` の `findRoute`）：本番と同一のジオメトリ（`enemyPlanning/planningEnv.ts` の `buildPlanningEnv`＝solids/rects/carves/kind を本番 `isSolidAt` と同一判定で参照）上で、グリッド A*（8近傍・ユークリッド距離コスト・`gridStep=0.75`・展開上限 `maxExpansions=12000`）＋見通し線ショートカット（`smoothingPasses=3` パス）を行い、折れ線経路を作る。素材に `clearance` 未満で触れない `clean` モードと、削れる壁を直線で掘ってよい `wallTunnel` モード（トンネルは直線・本数 `maxTunnelCount=1` 以下・長さ `maxTunnelLength=8` 以下、`unbreakable` は常に遮断・壁内部の蛇行は禁止）がある。
2. **family フィット**（`enemyPlanning/routeFit.ts` の `fitRouteToFamilies`）：敵位置を原点、ゴール方向を +x とする局所フレームへ経路を写し、通過点を通る `g(x)` を `abs`/`arc`/`poly34`（＋終盤の `harmonic`）の各 family へ最小二乗フィットする。**まず経路長に沿って等間隔へ取り直す**（#69）：A*＋見通し線ショートカットの折れ線は角の付近に点が密集するため、そのまま最小二乗にかけると「角だけに合わせて全体を外す」過重みになる。`poly34` がフィットする次数、`abs` に重ねられる折れ点の枚数、`harmonic` の項数と「掛け合わせる包絡」の本数は、**敵の LVL で決まる**（#70・[05b](05b-enemy-archetypes.md) §2.1）：LVL1〜2 は1〜2次、LVL3〜4 は3次まで、LVL5〜6 は3・5次＋折れ2枚＋指数包絡、LVL7 は7次・折れ4枚・`exp×cos` の積まで。高次ほど経路に密着でき、柱の隙間のように何度も向きを変える道を1本の式で通せる。多項式の基底は `u=x/L` に正規化して解く（7次でも正規方程式が破綻しない）。`harmonic` は**フーリエ正弦級数** `g(x)=Σₖ cₖ·sin(kπx/L)`（k=1..`harmonicMaxTerms`）でフィットする：基底が `g(0)=g(L)=0` を**厳密に**満たすので、通過点をどれだけ攻めても**狙点は必ず通る**。係数は通過点への最小二乗＋高周波リッジ（`λ·k²`・`harmonicRidge`）で決め、「通過点は通るが暴れる」過適合を避ける。`g` に線形項 `b·x` を許すため、局所フレームがせん断されても family の形状（V字/放物線/S字等）自体は崩れない。局所 x がほぼ単調増加でない経路（後退許容 `monotoneBacktrackEps=0.35` を超える）はそのfamilyを諦める。
3. **本番物理検証**（`enemyPlanning/evaluate.ts` の `evaluateEnemyShot`）：候補軌道を、本番と同一の `carveAlong`（`src/game/carve.ts`）・`OBSTACLE_STEP` 密度・結界の相互相殺で解決する。経由点はフィットの入力にすぎず保証ではない――採用は必ずこの層の再検証を通った結果で決める。

流れ：

1. **guardian** なら防御結界を張って終了（`planGuardianBarrier`・05b §5.4／#71：外形と z 場を制約付きで最適化する。素材に触れない外形が組めなければ `null`＝このターンは張らない）。
2. **ruptor** なら専用の暴発計画（`planRuptorShot`・§5.4b）へ委譲する。
3. **隠蔽**：闇の周回で完全に隠れた味方（`concealed ≥ orbitConcealFull`）は視認不可＝狙えない。全員隠れていれば見えないなりに撃つ。
4. **breaker**（火力型）は family 制限なし・経路探索は使わず直進で削って進む。**attacker**（迂回型）は `abs`/`arc`/`poly34` のみ（`avoiderFamiliesOf`・#46）。
5. 各味方について、まず「狙い角 × 形状係数 × z 場強さ」の直接 family 候補を評価する。attacker はどの候補もクリーン命中（下記ランクの `rank[0]=0`）にならなければ、`clean` 経路探索→family フィットの候補を追加する。**経路は「広い車線」を優先して2本探す**（#69）：素材から `wideClearance=1.5` 離れた経路をまず探し、無ければ通常の `clearance` でも探して両方をフィット候補にする。弾は硬い壁に**一度触れただけで失速して消える**（初速8に対し tough の削りコストは中立で 11.9）ため、隙間のギリギリを縫う経路はフィット誤差でほぼ確実に潰れる。それでも全味方を通してクリーン命中が1つも無ければ、最後に全味方について `wallTunnel` 経路探索の候補（壁削り）を追加する。

### z 場の強さ候補（#31）

```ts
ATTACK_Z_MAGS = [zPeak(=5), zRef(=2.5)]
```

対象の反対極を、`zPeak`（近距離で大威力だが減速）と `zRef`（中遠でも届く）の両方で試す。`castZField` を持つ敵はそれ 1 つを使う。

### 辞書式ランク（`compareRank`・小さいほど良い）

各候補は `evaluateEnemyShot` で本番と同一の削り・結界減速を通した `flight` に対し `firstHit(flight, aimPos, allyHitbox)` で命中判定する。**失速して届かない候補（`hit.speed≤0`）／命中前に `unbreakable` の素材を横切る候補は、ロールを問わず候補にすらならない**（棄却＝物理的に届かないため）。逆にいえば、**届く候補は必ず候補に残る**：命中前に壁内部で折れる候補（`turnsBefore>0`）は #70 で**棄却をやめ、rank による降格に変えた**（命中を最優先する。第0要素・第1要素で必ず下位に沈むので、クリーン命中も「壁の中で曲がらない貫通命中」も無いときにだけ選ばれる）。

```ts
rank = [
  breaker ? 0 : matBefore > 0 ? 2 : 0, // clean=0 / 壁削り(wallTunnel)=2。breaker は常に0
  turnsBefore,   // 命中前に壁内部で折れた点の数（0が最良）
  ringsBefore,   // 命中前に横断した反対極結界の数
  -score,        // 期待ダメージ（大きいほど良い→符号反転で昇順比較に載せる）
  hit.arcLen,    // 命中までの弧長（同条件なら短い方）
]
```

第0要素が最優先で比較される（辞書式）ため、**クリーン命中（`rank[0]=0`）がどの味方に対して1つでもあれば、壁を削る候補（`rank[0]=2`）は絶対に選ばれない**。

### スコア（`score`）

```ts
hz = breaker ? zVal : zfieldAt(traj, hit.pos)
// 迂回型：命中点の z 場の実属性・実強度（削り・結界減速込みの実速度 hit.speed と組み合わせて評価）
// 火力型：代表 zVal（zPeak/zRef やランプ場の狙い値）で採点＝「直進の火力弾」の設計を維持
//         （命中点 z で採点すると「横から回り込んで zPeak ちょうどで当てる」曲線を選んでしまうため）
baseDmg = hit.speed × strengthOf(hz) × affinityMultiplier(attributeOf(hz), ally.element) × maneuver
killBonus  = baseDmg ≥ ally.hp ? 2.2 : 1     // とどめ最優先
woundFocus = 1 + (1 − hp/maxHp) × 0.5         // 手負い優先
lowHpBias  = 1 + max(0,(60 − hp)/60) × 0.25   // 低HP微優先
score = baseDmg × killBonus × woundFocus × lowHpBias
```

`maneuver` は迂回の取り回しコスト：family 直接候補=1、経路探索フィット由来（clean/wallTunnel）=`MANEUVER=0.9`。同条件なら直進/貫通が勝つ。

### 掘削フォールバック（全ロール・#64／#70）

どの候補も命中しない＝壁が厚いときは、牽制でお茶を濁さず**壁を掘り進める**（#64 で火力型に導入し、#70 で**迂回型を含む全ロール**へ拡張した：到達不可なら障害物に当ててでも相手へ向かう）。命中判定に落ちた各候補（`consider` の不達候補）について「停止点（飛行の最終サンプル）が狙い（`aimPos`）に最も近い」＝**carve の速度損込みで1番奥まで掘れる**候補を記録し（`trackDrill`）、それを布石として選ぶ（`expectedDamage=0`）。ただし**「掘れば道が開く」見込みのない候補は掘削にしない**（不可解な壁撃ちの修正）：

- 素材を一度も削らない候補（失速・逸れただけ）は掘削でない＝対象外。
- **障害物なしの自由飛行が狙いのヒットボックスへ届かない候補は対象外**：z 減速で失速して届かない弾は、掘って壁の速度損を消しても永遠に届かない（従来は掘削に選ばれ続け、毎ターン角度を変えて壁を掘る「不可解な壁撃ち」になっていた）。
- **狙いへ達する前に `unbreakable`（削れない壁）を横切る経路は対象外**：掘り進めても必ずそこで止まる＝トンネルは開通しない（従来は「unbreakable に当たって止まった」候補だけ除外していたため、その手前の削れる壁で止まっている間は死路を掘り続けていた）。

掘削候補どうしの優先順位（辞書式・#69／#70）：

```ts
drillRank = [
  materialLenAfter,        // ① この一撃のあと、狙いまでに残る素材の長さ（最小＝あと少しで貫通）
  -(materialLenBefore - materialLenAfter), // ② 削り取った素材の長さ（最大＝仕事量が多い）
  dist(停止点, aimPos),     // ③ 狙いの近くまで到達している
  freeHit.arcLen,          // ④ 相手へ最短で届く経路（#70：遠回りの掘削を選ばない）
]
```

ランプ z 場（05b §5.1）は飛行中 |z|≈0＝最大加速で**高速のまま壁に当たり、えぐり半径（威力=速度×(強度+1) 比例）も大きい**ため、掘削の最深到達も自然にランプ候補が担う。毎ターン同じ狙いへ掘り足せば数ターンで貫通し、命中候補が成立した時点で通常の採点へ戻る。

高難度（LVL≥`COMBAT.breakerDrillMinLevel`(=5)）の火力型は、掘削用の弱い一定場 `|z|=COMBAT.breakerDrillZ`(=1.5) を**両極とも**候補に持つ（05b §5.1）。壁の反対極の z なら削りの速度損が ×0.5 になり、色つきの壁をおまかせ（`RECOMMEND.zWeak`＝対象の反対極のみ）より速く掘り抜ける。

### 牽制（フォールバック）

どの候補も命中見込みなし（命中スコア無し）のとき：

1. **breaker** は上記の掘削候補があればそれを選ぶ（牽制より優先・#64）。
2. 狙う相手が**結界に囲まれて突破できない**場合は、**結界そのものに反対極（zRef）を当てて削る**（得意関数から実際に境界を横切る軌道を、終点方向の補正つきで選ぶ・05b §1「避けられないなら結界に当てる」）。
3. **迂回型もここで掘削候補があればそれを選ぶ（#70）**：牽制（当たらない一撃）より、狙いまでに残る素材が最小＝相手へ最短で届く経路を掘る方が常に良い。
4. それ以外（掘っても道が開かない＝`unbreakable` や z 減速で物理的に届かない）は、最も HP の低い見える味方へ**得意関数で牽制**（減速しない zRef で撃つ。`line` を持たない個体＝迂回型/暴発型は曲線で撃つ）。

## 5.4b 崩し手の狙い（`planRuptorShot`・#42）

`ruptor` は通常の最大ダメージ探索（`consider`）を使わず、**専用の計画関数**で「誰の／どこの近くで暴発させるか」だけを決める。狙う対象の**手前**に破綻点を作る点が、他ロールと根本的に異なる。

> **原則**：`ruptor` は AI の狙い方が特殊なだけで、**物理法則・干渉ルールは味方と完全に同一**。飛行中の速度・加速度、周回リングやパリィによる迎撃、暴発そのものの挙動（04-magic §4.3）まで、既存のルールをそのまま適用する。専用の判定式・専用の免除は設けない。

### 1. 対象の選定

```ts
target = 見える味方の中で最もスコアの高い者（脅威優先度は attacker の woundFocus/lowHpBias と同様の考え方）
```

- 隠蔽（§5.5）の扱いは attacker と同じ：完全に隠れた味方は狙えない（`perceivedPos` を使う）。全員隠れていれば見かけ位置に対して計画する。
- **壁狙い個体（`enemy.ruptorTarget==='obstacles'`）は上記と独立の専用経路**（第4面デモ用・#42）：削れる素材（円・矩形とも・`materialCells`）のうち、**自爆圏より遠いセルだけ**（`disc.d − disc.r − 1.2 > selfDanger + 0.3`・#65：面の手前に置く極が自分の AoE 危険圏に入るセルは候補から除外）を敵に近い順へ最大 `maxGoalsPerEnemy(=6)` 件試し、各素材の**面の手前**（素材の外に出るまで敵側へ引いた点から、さらに敵側へ引いた点）へ極を仕込んで、確実に暴発でき・クリーンに（壁削り・結界横断なしで）届き・**自爆も味方巻き込みも無い**狙いを探す。見つかり次第採用、無ければ全候補中で最良ランクのものを採用する（ただし自爆になる暴発は採用しない・#65）。壁が全て崩れた・安全な壁が無いときは通常の味方狙いへフォールバックする。

### 2. 軌道と z 場の構築（3層探索＋辞書式ランク・`enemyPlanning/ruptorPlanner.ts`、05b-enemy-archetypes.md §4 が正典）

対象へ向かう軌道は、迂回型（§5.4）と**同じ3層構成**（幾何経路探索→family フィット→本番物理検証）で作る。使う family は個体の得意 family（`abs`/`arc`/`poly34` に絞った集合）を優先し、届かなければ主力 family 一式（`abs`/`arc`/`poly34`）・`clean` 経路探索・`wallTunnel` 経路探索の順にエスカレーションする（`searchAim`）。

**破綻させるのは軌道ではなく z 場**：`buildRuptorZField(origin, target, polarity)` が

```ts
g(x,y) = (x−rx)·ux + (y−ry)·uy          // 狙点までの相対位置(rx,ry)・単位方向(ux,uy)への符号付き投影。狙点で g=0
z(x,y) = RUPTOR.zBase(=2.2)·極性 + (−RUPTOR.poleK(=2)·極性) / g(x,y)
```

を仕込む。飛行区間は `zBase` の穏やかな光/闇属性を帯びた読み取り可能な弾として振る舞い、狙点へ近づき `g→0` に近づくほど `|z|` が発散して 04-magic §4.3 の「z場のエラーによる暴発」がその場で起きる（既存の極判定・二分法をそのまま使い、専用の破綻フラグは設けない）。

- 暴発点は対象のごく近傍になる。威力・範囲・付与状態異常は 04-magic §4.3 の暴発と完全に同一（**常に最大**：`power = sMax × maxFlightSpeed`、対象に対し常に有利側 ×1.5、光のひるみ＋闇の継続ダメージを両方付与）。`instability`（04b §4b.1）も、この暴発が**解決すれば**（＝迎撃されなければ）通常の暴発と同じく +1 される。
- 極に達するまでの飛行区間は、`polarity`（弾の極性）の符号に応じた通常の光/闇属性（強さ `zBase`）を帯びた**ただの弾**。属性の読み方・迎撃のされ方は§4「迎撃ルール」のとおり、他の敵弾と全く同じ。

#### 被覆（`Cover`）：点（ユニット狙い）と素材（壁狙い）の分離（#63）

AoE が「何を巻き込めば有効か」を表す `Cover` は2種類ある（`enemyPlanning/ruptorPlanner.ts`）：

```ts
type Cover = { kind: 'point'; pos: Vec2 } | { kind: 'material' }
```

- `point`：ユニット狙い。暴発点からその位置までの距離で判定する（対象そのもの、または壁手前補正時に併走させる対象付近の候補）。
- `material`：壁狙い。暴発点を中心に半径 `aoeRadius`／`guaranteed` の円が、削れる（`unbreakable` 以外の）壁素材のいずれかと重なるか（`obstacleOverlapsCircle`）で判定する。

壁越しにユニットを狙う局面（`wallFrontAim` が補正を掛ける局面）では、**壁面手前（素材被覆）の候補だけでなく、対象付近を曲線で狙う点被覆の候補も必ず併走させる**。回廊・隙間があれば点被覆（ユニットを直接巻き込む）が壁削りより常に優先される（後述の rank 第2キー）。壁が完全に塞がっていて点被覆が成立しないときだけ、壁面手前へ落ちて「壁を削って積む」動作になる。

#### 暴発成立（`misfire`）の判定と辞書式ランク

候補ごとに `evaluateEnemyShot` で本番物理（削り・結界相殺込み）を通し、次のすべてを満たす候補だけが実際に暴発する（`misfire=true`）：

- `ruptured`：軌道が極（z 場の無効点）に到達する
- `!stalled`：削り・結界減速で失速していない
- 反対極の持続結界の**迎撃圏**（`ringRadius＋ringFrontMargin(=1.6)`）に極が踏み込まない――防御側が結界半径を広げて迎撃範囲を手前まで伸ばす対抗策を、暴発 AI が押し切らないための条件
- 被覆（`Cover`）が暴発点から `aoeRadius(=5)` 以内で有効（`inExpected`）――圏外で誰も何も巻き込めない暴発は採用せず、通常弾へ切り替える

**暴発予告（`misfirePos`）は `misfire=true` の候補にしか出さない**――暴発しない見込みの候補を予告することはない。

```ts
guaranteed = FIELD.aoeRadius × (1 − varianceOf(instability))  // instability 下振れ込みでも巻き込める半径（04b §4b.3）
selfDanger = FIELD.aoeRadius × (1 + varianceOf(instability))  // 自爆・味方巻き込みの危険圏＝上振れ込みの最大半径（#65）
inGuaranteed = covers(cover, endPos, guaranteed)   // 下振れ込みでも被覆を巻き込める
inExpected = covers(cover, endPos, FIELD.aoeRadius) // 期待半径でなら被覆を巻き込める
selfInAoE = misfire && dist(endPos, enemy.pos) <= selfDanger       // 自分を巻き込みうる極（上振れ込み）
matesInAoE = misfire ? 生存中の味方（敵チーム）で selfDanger 内に入る数 : 0
rank = [
  misfire ? 0 : 1,                       // 暴発が実際に成立するか
  misfire && cover.kind === 'point' ? 0 : 1, // ユニット被覆を壁削り被覆より常に優先（§14.2）
  selfInAoE ? 1 : 0,                      // 自爆の回避（§12.7 selfInsideAoE／#65：被覆より優先）
  matesInAoE,                             // 味方（敵チーム）巻き込み数の回避（#65）
  inGuaranteed ? 0 : 1,                   // 下振れ込みでも巻き込める（本命）
  inExpected ? 0 : 1,                     // 期待半径でなら巻き込める（次点）
  hitBeforePole ? 1 : 0,                 // 極到達前に対象のヒットボックスへ通常接触してしまうか
  unbreakableArc !== null ? 1 : 0,       // unbreakable 横断は避ける
  turnInMaterialArcs.length,             // 壁内部の折れ点
  materialArcs.length > 0 ? 1 : 0,       // クリーンを壁削りより優先
  oppositeRingArcs.length,               // 反対極結界の横断数
  ownFam ? 0 : 1,                         // 個体の得意 family の個性を保つ
  dPole,                                  // 極までの距離
  max(0, dCover − guaranteed),            // guaranteed 超過分
  pathLength,
]
```

`instability` が misfireLimit に近づき半径のブレが大きいほど（04b §4b.3）、`guaranteed`（下振れ時でも確実に届く半径）を満たす候補が優先される＝プレイヤーへの脅威が下がらない。

- **自爆・味方巻き込みの回避（`planRuptorShot` の `teammates` 引数・#63/#65）**：暴発は敵味方無差別に巻き込むため、`enemyAI.ts` の `planEnemyShot` は `ruptor` へ計画を委譲する際、生存中の敵チーム（`teammates`）を渡す。`selfInAoE`/`matesInAoE` は rank で**被覆キー（inGuaranteed/inExpected）より上位**に置かれる（#65）――「確実に巻き込める極」より「自爆しない極（横へ逃がした極）」を必ず優先する。危険圏は AoE 半径の**上振れ込み**（`selfDanger`）で見積もる（instability が高いほど広く取って安全側に倒す）。

#### 狙点候補（`aims`）：手前補正と素通り回避

狙点は状況に応じて切り替える：

1. **結界に囲まれた対象**：`ringFrontAim` が迎撃圏の手前（敵側）へ極を引く（`slipThrough` で同極透過できるときは補正しない＝奥まで届かせる。§5.3）。
2. さらに**壁に阻まれる**（削れる／砕けぬを問わず敵→対象の直線が素材に触れる）なら `wallFrontAim` が壁の素材へ触れる直前まで手前へ引く（`wallFrontMargin(=1.8)`）。この局面では**点被覆（対象付近を曲線で狙う候補）と素材被覆（壁面手前）の両方**を候補に並べる（`pushPointAims`＋壁手前1点）。回廊・隙間があって点被覆が成立するならそちらが rank で優先され（前述）、対象付近で暴発する。届かないときだけ素材被覆に落ち、「壁を削ること自体」が有効範囲になる（狙う味方が壁帯の奥に居ても、手前で暴発させれば弾は壁に阻まれず極まで達し、削れる壁なら AoE が壁も崩す。砕けぬ壁でも「暴発は必ず起こる」＝崩せはしないが積みは成立）。
3. **補正が掛からない開けた盤面**：対象中心だと弾が先にヒットボックスへ通常接触し「対象を素通りして奥で暴発する」不自然な見た目になるため、対象の**手前**（狙う方向へ `allyHitbox+0.9`）・**横2方向**（法線方向へ `allyHitbox+1.2`）に極候補を並べ、それでも決まらなければ最後に対象中心を候補に加える（すべて点被覆）。

`aims` の全候補（各自の `Cover`＝点 or 素材を伴う）を通して最良ランクを採用する。

- **結界（周回リング）を狙う場合（#48）**：これは特例ではない――手前に至るまでの飛行区間は他の弾と全く同じ物理法則に従う。その手前の点へ至る経路上で、範囲の広い別のリングや、狙いすましたパリィに引っかかれば、通常どおり迎撃・消滅する（misfire 判定も `stalled` により自動的に false になる）。プレイヤー側の対抗策は「リングの半径を広げて迎撃範囲を手前まで伸ばす」「パリィで経路上を狙い撃つ」の2つ。

### 3. 予告（テレグラフ）

対詠の晒しフェーズで、他ロールと同様にゴースト軌道を見せる。加えて、**破綻点（暴発点）に警告マーカー**（プレイヤー自身の暴発プレビューと同じ赤い✕・揺れる円）を重ねて表示する。プレイヤーは着弾前に対応判断ができる。

### 4. 迎撃ルール（味方の弾と全く同じ物理法則に従う）

`ruptor` の弾も、**味方の弾と特別扱いを一切せず、既存のルールがそのまま適用される**。

- **属性**：破綻するまでの飛行区間は、他の敵弾と同様に `element`（またはその敵固有の `castZ`/`castZField`）に基づく通常の光/闇の弾。**極性はゴースト・弾の見た目から読み取れる**（他ロールと同じ予告の仕組み）。
- **周回迎撃**：結界（周回リング）が触れたときの解決は 04-magic §4.6 の通常ルールそのまま――**反対極のみ相殺、同極・中立は透過**。ruptor の弾を止めたいなら、**その弾の属性と反対の理を帯びたリングを、破綻点（暴発点）へ到達する前に間に合わせる**必要がある。同極のリングでは素通りする。
- **パリィ**：味方の発射型弾との交差も 04-magic §4.5 の通常ルールそのまま――反対極のときだけ威力を引き算し、必ずどちらかが消える。
- **速度 0 なら消滅＝暴発しない**：迎撃・相殺で弾の速度が 0 になれば、他のあらゆる魔法弾と同じく**その場で霧散**する。破綻点まで届かなければ式は評価されず、暴発は起こらない。`instability`（04b §4b.1）も加算されない。
- 結界が威力で負ければ（弾威力 > 横断点のリング威力）、そのリングは他の敵弾を防ぎ損ねた場合と同じく丸ごと霧散し、弾は残威力で破綻点まで飛び続けて暴発する。
- ひるみ（光の状態異常）は、他ロールの敵弾と同じ扱い：**既に放たれた飛行中の弾には影響しない**（次ターンの詠唱を阻害する効果であり、in-flight の弾を止める手段ではない点は attacker/breaker と同じ）。

> つまり `ruptor` を防ぐ手段は、通常の迎撃・パリィと**全く同じ読み合い**――弾の属性を見て、反対の理で結界を張るかパリィで迎え撃つか。特別なメカニクスは存在しない。**迎撃に成功するかどうかは `instability` の増分に直結する。**崩し手を防ぎ続けられれば暴発の回数を抑えられ、後半のメーター（04b-misfire-instability.md §4b.2）に余裕が残る。

## 5.5 隠蔽への対応（`perceivedPos`・#35/#39）

闇の周回で隠れた味方は、敵から見て真の位置からずれて見える。

```ts
ブレ幅 mag = concealRmse（囲む円半径連動・1重=半径/2, 2重=半径）
            または重数 × CONCEAL_JITTER(=3.5)（旧データ）
見かけ位置 = 真位置 + idDir(id) × mag
```

方向は ID 由来で安定（純粋関数を保つ＝同ターンの再評価で揺らがない）。敵はこの見かけ位置に対して狙い・命中評価を行う。
